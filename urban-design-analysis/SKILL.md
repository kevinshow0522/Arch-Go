# 城市设计分析图 v1.1

版本：v1.1（2026-10-19）。v1.0定下静态分析图方法；v1.1加入第十一节“交互展示（07.2）”。
来源：六份城市设计参考文本（临港张江科技港 HASSELL＋中规院、新桥东 HASSELL＋深规院、昆山杜克智谷 SASAKI、佛山时代创客小镇、西湾街里 深规院联合体、解溪一号方案），共818页，约480页分析图。依据见《分析图画法与表达｜城市设计参考 v1.0》文档、《城市设计分析图样板》和《交互分析展示原型》页面。

适用：城市设计、片区规划、城市更新、建筑项目的场地与周边分析（工作流01–05章的分析图）；把这些分析图做成工作台07.2的交互展示。
不适用：效果图（交给出图工具）；建筑单体尺度的画法（另建建筑单体分析skill后再用）。

## 一、工作步骤

1. **先写问题和结论。** 每张图开画前写两行：这张图回答什么问题；结论是什么。结论就是图标题。写不出结论的图不画。
2. **确认底图。** 用项目自己的底图（CAD、测绘、规划图）；没有时用卫星图。两者都没有，只画抽象图解，不画伪精确平面。
3. **选风格。** 从第四节选一组配色，整个项目不换。用户指定的风格优先。
4. **选模板。** 按第八节的章节对照和第七节的模板选组织方式。
5. **定底图体系。** 一个项目只用三到四套底图；同一套底图的裁切、比例、指北针和比例尺位置全程不变。
6. **分层画。** 底图层、系统层、介入层、标注层分组，每组命名（见第九节）。分层是交互展示的前提。
7. **校核。** 逐条过第十节清单后再交付。
8. **交付。** 每张图附：问题、结论、底图来源、数据来源、待核事项。需要给甲方点看时，按第十一节组装成07.2交互展示。

## 二、八条核心规则

1. 一页一问，标题即结论。标题写判断句或问句，不写“××分析图”。
2. 结论必须能被图证明。标题说“覆盖不足”，图上就要有覆盖圈和缺口。
3. 底图是一套系统：同底、同裁切、同视角，每页只换一层。
4. 底图退后：去色、压暗或淡化；每页主题层只用一到两种饱和色，一张图不超过六种颜色。
5. 颜色全书同义：一个颜色一旦代表某个系统，全项目不再代表别的。
6. 用序列、分层和对照讲逻辑，不把所有要素堆在一张图上。
7. 结论数字化：“2+2 区域交通”“22.8% 蓝绿空间”“2廊·1环·3节点”。数字必须有来源，概念阶段取整。
8. 出图前必须校核。参考的六份成熟文本全部存在图文矛盾、图例错配或拼写错误。

## 三、底图

| 底图 | 处理 | 适合回答 |
| --- | --- | --- |
| 压暗的去色卫星图 | 去色、压暗；基地内白色半透明提亮，外部中灰；水系重新着水色 | 区位、现状、规划条件 |
| 浅色平面底 | 街块浅灰、道路留白、水浅、绿淡；指北针、比例尺固定一角 | 交通、开放空间、用地、设施等系统图 |
| 白模轴测 | 同一机位；建筑白或浅灰带柔影；基地外缘虚线；可把地形染一种浅色 | 原则、策略、结构、形态、视线高度 |
| 抽象图解底 | 不用地图，只留基地轮廓或拓扑；或把要素重画在深色底上 | 概念、结构、观点总结 |
| 剖面立面底 | 单线立面或白模剖切；地坪以下一条深色实带 | 天际线、竖向、生态原理 |

- 越往后越淡、越抽象：现状用压暗卫星图，设计阶段用浅色平面或白模。
- 先分析、再重绘总结：同一组要素先在卫星图上分析，再抽离到深色底上做观点页。
- 局部聚焦：全局蒹白60%–70%，当前分区保留原色并加彩色描边。
- 白模轴测由用户从SketchUp或Rhino导出，分析层叠在上面；不自造与模型不符的体量。
- 禁止：彩色卫星图不压暗；彩色上位规划图直接做底；荧光色卫星图；效果级景观做底；底图淡到无法定位。

### 新增风格的格式

新风格按上表增加一行，十一个色值全部给出，并写明：风格名、来源（哪个参考或哪个项目）、适合场景、与现有风格的区别。新增前先在样板页上切换验证：介入色在底图上是否醒目、四种系统色是否可区分、小字是否可读。

## 六、文字与标注

- 标题三种写法：判断句；问句（问题页）；“主题：结论”对仗短语。
- 图内结论标签：大号数字＋一行中文，放在固定角落，带纸底色背板。
- 结构图例用“大数字＋色条＋名称”，色条即图上要素颜色。
- 数值直接写在图上（容积率写在地块上，高度用深底白字标签，半径写在半径箭头上）。
- 一页只有一个主题时可以不要图例；多于一个必须有，或让标签与要素同色。
- 平面图必须有指北针和比例尺，位置固定；轴测、拓扑和剖面示意不配。
- 中英双语不是默认；用户要求时才加，并逐条校对。
- 字号（按A3横版输出）：页标题≥18pt；图内结论数字≥18pt；图内标签≥8pt。
- 字体：Segoe UI、Microsoft YaHei，或项目指定字体。

## 七、模板

核心五种（样板已画）：T1、T2、T3、T4、T7。其余按需启用。

**T1 同底四联**（佛山p39、p41；新桥东p41）
- 同一底图四格，同裁切、同比例；每格只叠一种要素、一种系统色。
- 每格左上或左下一个数字化结论标签；格下写编号和主题。
- 页标题是四格合起来的判断。可变体：每格下配一条剖面。

**T2 问题对策略**（新桥东p28–p31→p39–p73；西湾p27–p29；临港p13→p14）
- 左侧问句＋暗底，只亮出问题所在并打“？”；右侧判断句＋浅底，只画回答这个问题的一个动作。
- 两侧同底、同裁切。后文策略按问答顺序逐条展开。

**T3 生成序列**（解溪p82–p83；西湾p30；临港p27、p31；佛山p92）
- 同底同比例3–4步，每步只加一层；新加的层实色，之前的层淡化到约40%。
- 每步一个编号和一句动词短语。最后一步即完整结构。

**T4 分层再叠合**（新桥东p36；西湾p38；解溪p85、p101）
- 三到四张单层小图（底图淡化、可省指北针）＋一张叠合大图＋“大数字＋色条”图例。
- 变体：把总图裁成几个圆，每圆只亮一个要素。

**T7 图解与落地成对**（佛山p43、p50与p51、p54与p55；解溪p131）
- 左拓扑简图（不画比例，只画谁连谁），右落地平面或轴测；两张同名同色。
- 变体“三件套”：口号结论＋结构简图＋落地平面。

## 九、实现规范（SVG）

- 输出：自包含HTML，内嵌SVG；一张图板一个文件或一页多板。不用外部图片，底图影像以data URI嵌入或从项目文件引用。
- **同一几何。** 底图和各层坐标写在一个共用对象里（边界、道路、水系、廊道、节点、组团），静态图板和交互展示都从它生成，保证同底、同位。
- **同一裁切。** 同一套底图用同一个viewBox；基地占画面约60%。指北针在右上、比例尺在右下、结论标签在左上，全项目不动。
- **颜色用变量。** 只引用 `--b-paper` `--b-block` `--b-line` `--b-ink` `--b-muted` `--b-water` `--b-green` `--b-traffic` `--b-zone` `--b-mark` `--b-text`，换风格只换变量值。不写死色值。在SVG里用 `style="fill:var(--b-water)"`，不用fill属性引用变量。
- **分层命名。** 每个图层一个 `<g>`，写 `data-layer` 和 `data-role`：
  - `data-role`：`base`（底图）、`system`（现状或系统）、`move`（方案介入）、`note`（标注与结论）。
  - `data-layer`：层名，如 `river` `corridors` `ring` `nodes` `zones`，全项目同名同义。
  - 生成序列中的层加 `data-step="1"` 等。
- 文字压在图上时用 `paint-order:stroke` 加纸底色描边保证可读。
- 默认画法片段：

```js
const G = { site:'x,y …', river:'M…', main:['M…'], corA:'M…', ring:'M… A… Z', nodes:[{x,y,name,q,text}], zones:['x,y …'] };
const layer = (role, name, inner, step) =>
  `<g class="layer" data-role="${role}" data-layer="${name}"${step ? ` data-step="${step}"` : ''}>${inner}</g>`;
// 廊道：宽带 + 白色虚中线
const corridor = d => `<path d="${d}" style="fill:none;stroke:var(--b-green);stroke-width:22;opacity:.8;stroke-linecap:round"/>`
                    + `<path d="${d}" style="fill:none;stroke:var(--b-paper);stroke-width:1.5;stroke-dasharray:6 5"/>`;
// 节点：光晕 + 实心
const node = (x, y) => `<circle cx="${x}" cy="${y}" r="22" style="fill:var(--b-mark);opacity:.22"/>`
                     + `<circle cx="${x}" cy="${y}" r="9" style="fill:var(--b-mark);stroke:var(--b-paper);stroke-width:2"/>`;
```

- 画完在浏览器里截图看一遍：文字是否压线、被裁切，颜色是否可区分。切换到至少一组其他风格再看一遍。

## 十、校核清单

- [ ] 标题的结论在图上有对应图层。
- [ ] 数量、数值、方向图文一致（几条、几个、多高、哪一期）。
- [ ] 标题与图内标签一致。
- [ ] 图例与图面一一对应：不颠倒、不重复、不缺项。
- [ ] 同一颜色、线型与项目已出图同义。
- [ ] 数值用顺序色阶，类别用区分色。
- [ ] 不做伪精确：不写无来源的数字和百分比，不画词云，不放无单位无图例的图表，概念阶段取整。
- [ ] 平面图有指北针和比例尺，位置与同系列一致。
- [ ] 无错字、占位符、空信息框；英文（如有）与中文一致。
- [ ] 编号与目录一致。
- [ ] 分析页不堆意向照片；不用带水印或在线地图截屏。
- [ ] 单页输出时大图不跨装订线。
- [ ] 虚构或示例数据已标明。
- [ ] 交互展示另过第十一节的交互校核。

## 十一、交互展示（07.2）

用途：给甲方自己点着看，放在工作台07.2交互界面展示。组织方式是“主图、点位、说明联动”。交互只用来表达顺序、对照和关系，不做装饰。原型见《交互分析展示原型》页面。

### 11.1 页面结构

- 顶部：项目名；右侧注“交互展示 07.2”和数据说明（如“示例数据”）。
- 左侧主图：一张SVG，底图和所有图层一次画好，按 `data-layer` 切换显示，不重画。
- 右侧说明面板：“第n / N步 · 短名”，标题（即结论），一行操作提示，控件，说明卡（不超过三行）。
- 底部：上一步／下一步＋步骤点；键盘左右键翻页。
- 桌面左右布局，窄屏上图下文；无横向滚动；触屏可点可拖。
- 外框沿用03.1语言（纸白底、1px线、近直角、暖色标选中）；图面用项目风格。
- 不加与AI交流的入口，不写入项目数据。

### 11.2 默认五步（按项目增减）

| 步 | 短名 | 来自模板 | 交互 | 标题写法 |
| --- | --- | --- | --- | --- |
| 1 | 现状 | T1 | 图层切换：点一项只显示一个系统，左上角显示其数字结论 | 四项合起来的判断 |
| 2 | 问题 | T2 | 分割线对比：选问题，左右拖动分割线比较问题与回应 | “几个问题，几个回应”或总判断 |
| 3 | 生成 | T3 | 逐层生长：点步骤或播放，新层画出，之前的层淡化 | 生成逻辑一句话 |
| 4 | 结构 | T4 | 图例联动：点“2 条绿廊”只亮该层，再点恢复 | “两廊、一环……”结构口号 |
| 5 | 节点 | T7落地图 | 节点点选：点节点，右侧显示做什么、回应哪个问题 | 一句结构结论 |

### 11.3 交互组件

| 组件 | 做法 |
| --- | --- |
| 图层切换 | 按钮组（aria-pressed）；只给选中层加 `on` |
| 分割线对比 | 两个clipPath：左侧叠D暗底半透明并画问题层与“？”，右侧画回应层；分割线带手柄；“问题／回应”标签跟随分割线；可在地图上直接拖，也可用图下滑杆 |
| 逐层生长 | 线状要素用mask内同路径 `pathLength="1"`、`stroke-dasharray:1`，从 `stroke-dashoffset:1` 过渡到 `0`（约1.1s），以保留虚线等线型；当前步实色，之前步 `dim`；播放每步约1.5s |
| 图例联动 | 图例项做成按钮（大数字＋色条＋名称）；选中层 `on`，其余 `faint`；再点恢复 |
| 节点点选 | 节点 `<g>` 加 `tabindex="0"`、`role="button"`、`aria-label`，回车可选；选中时光晕放大1.6倍；说明卡写名称、做什么、回应哪个问题 |

层状态统一用四个类：默认隐藏（0）、`on`（1）、`dim`（0.35）、`faint`（0.1），用opacity过渡0.5s。状态放在一个对象里（如 `{step, sys, q, gen, leg, node, split}`），一个 `render()` 根据状态计算每层的类并刷新说明面板。

### 11.5 规则

- 一次只动一件事；动画时长0.5–1.2秒；不自动循环播放。
- 静止时也读得懂：每个状态都有结论文字，不依赖动画才能看懂。
- 遵守 `prefers-reduced-motion`：关闭过渡，直接显示结果。
- 给甲方的文字：每步标题即结论，一行操作提示，说明卡不超过三行；不用专业缩写。
- 所有可点元素都能用键盘操作，焦点可见。
- 未经确认的内容不进交互展示；示例或待核数据必须标明。

### 11.6 交互校核

- [ ] 每一步、每个控件都点过一遍，状态与说明一致。
- [ ] 桌面与手机宽度各截图一次；无横向滚动，文字不被遮挡。
- [ ] 无控制台报错。
- [ ] 分割线在两端时标签与指北针、比例尺不重叠。
- [ ] 关闭动画（reduced motion）时仍可完整浏览。
