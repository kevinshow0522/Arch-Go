# KI建筑设计工作流 1.30

本 skill 只管各章共用的东西：章节与阶段、工作包怎么拆、调哪个章节 skill、等级与编号怎么写、主线卡和交接记录、成果存在哪里。各章怎么研究、怎么判断，在章节 skill 里写，本 skill 不重复。两边说法不一致时，等级、编号、主线卡、交接以本 skill 为准，章节方法以章节 skill 为准。

## 1 原则

1. **AI 主导**：用户给目标、线索和取舍，AI 组织工作、执行、核对并保存。用户不必先选章节或填表。
2. **对话是唯一操作入口**；工作台只读，只看进度和最后的表达输出。用户的确认由 AI 在对话里写成记录，不靠对话记忆。
3. **每样东西一个正本**：项目事实、主线卡、指标表、交接记录各存一处（见第 9 节），两个 AI 读写同一份。
4. **范围是建筑概念与方案设计**：结构、机电、规范审查等不展开，需要时写成“专业接口”。
5. **按项目取舍**：章节、条目和标题是默认版本，每个项目由 AI 拟出项目目录与用户讨论；不凑全，不为填表而分析。案例不凑数。
6. **分工**：图片生成（效果图、意向图、场景图）交 GPT；分析图和交互界面动效由 Claude 做；其他谁接到谁做。一个任务同一时间只有一个执行者（Claude / GPT / 用户）。

## 4 开工与停手

每个工作包都走同样五步：

1. **开工**：确认项目、当前阶段和本次工作包；读最近的交接记录、主线卡（注意版本）、资料清单（`工作文件/资料清单.md`），以及本包要用的上游章末结论。不读其他对话的聊天内容。判断建筑类型，读 brief-and-metrics 里对应的类型参考卡。
2. **说明要读什么，问一次**：列出本轮要读的资料（从资料清单里挑，加上要用的参考库内容）和要写到哪里，问用户一次。得到同意后本包内按这个范围连续做（见第 9 节）。
3. **干活**：调用对应章节 skill，只做本包条目。需要参考库时先查参考库索引，只读相关的几页。遇到不属于自己的工作（如效果图），另建任务注明交给谁，不在本对话里等待。
4. **存成果**：过程放“工作文件”，成果放“成果输出”，记录存到正本位置（第 9 节），注明引用的主线卡、指标表、类型卡版本。用户在对话里做的确认写成确认记录。
5. **停手交接**：写一条交接记录（第 7 节：做完什么、下一步、还在等用户回答的问题、相关文件），再告诉用户“已交接”。

## 5 资料等级与可信度

**来源等级 A–E**（每条事实、每个数字都标）：A 正式文件 · B 甲方口头 · C 现场自测 · D 公开资料 · E AI 推断。

**可信度四档**（每条判断、每行数字、每张卡都标）：

| 标记 | 含义 |
| --- | --- |
| ✔ 确认 | 用户看过并确认，或对照原始文件核过 |
| ● 依据 | 来自 A–D 级来源，尚未确认 |
| ◐ 推断 | E 级，或 AI 由其他事实推出；必须写推断依据 |
| ○ 缺 | 知道需要，但还没有资料 |

这四档取代各 skill 里原来的“事实 / 推断 / 待核”“待核 / 已确认”“已核对 / 未核对”。对应：事实 → ●，推断 → ◐，待核 → ◐ 或 ○，已确认 / 已核对 → ✔，未核对 → ● 或 ◐。

规则：硬限制只能来自 ● 或 ✔；◐ 不能进指标表的目标行；AI 不能自己标 ✔；规范数值以用户的建筑设计专家库为准，并注明条文。

**案例等级甲 / 乙 / 丙 / 原理**（04 章专用，说的是案例资料能研究到哪一步，门槛见 case-study；case-study 里的 A/B/C 即甲/乙/丙）。不要和来源等级 A–E 混用。

工作台的条目状态（✓ 已确认、● 有成果、◐ 进行中、○ 未涉及、— 不适用）是工作进度，是另一条轴。

## 8 01 章：五张表

01 不另设 skill，用这五张表。

1. **资料清单**（`工作文件/资料清单.md`，Codex 盘点生成，AI 补来源等级和已读状态）：文件名 · 类型 · 来源等级 · 日期与版本 · 存放位置 · 已读 / 未读。
2. **已知事实**：事实 · 数值与单位 · 来源（文件与页码）· 来源等级 · 可信度 · 影响条目。
3. **缺口表**：缺什么 · 影响哪个条目 · 找谁要 · 不补会怎样。E 级内容只能进这张表，不进事实表。
4. **相关方**：谁 · 角色（提要求 / 出钱 / 使用 / 拍板 / 审批）· 关心什么 · 怎么联系。
5. **机会结论（01.5）**：值不值得推进 · 这一轮提供什么服务、到哪个阶段 · 需要什么条件 · 主要风险。简版可只写三句话。

## 9 成果存放与本地资料

**正本存放，按有没有项目服务工具分两种：**

| 情况 | 正本存在哪里 |
| --- | --- |
| 有 kg_ 工具（Codex，或已接上项目服务的 Claude 桌面版） | 项目服务：成果用 kg_save_result，确认、条件、主线卡、指标表、交接用 kg_save_record；开工先读 kg_get_context 或 kg_get_project_progress |
| 没有 kg_ 工具，但能打开项目文件夹（Claude 桌面版选了项目文件夹） | 项目文件夹 `工作文件/_KI记录/`：`主线卡_v0.3.md`、`指标表_v2.md`、`交接/YYYYMMDD-HHMM_W3.2.json`、`确认/YYYYMMDD_条目.md`；成果照常放“成果输出”。字段与项目服务相同，以后由 Codex 导入，不另造格式 |
| 都没有（云端对话） | 只讨论方法、改 skill；项目工作不在这里做。必须做时，把记录写成上面同样的文件交给用户，由用户放进项目文件夹 |

写入失败不能说“已保存”；没有工具时要说明成果在哪个文件里。

**本地项目文件夹**：每个项目四个区——项目资料、工作文件、成果输出三区可读写，第四区“参考库”只读（用户的建筑设计专家库和参考优秀文本）。资料清单（`工作文件/资料清单.md`）和参考库索引由 Codex 生成，开工时先读，不整库通读。每个工作包开工时问用户一次，说清要读写哪个项目、哪几个区；本包内按这个范围连续做，不逐次再问。超出范围（换项目、读别的文件夹、改用途）时再问；上一个包的同意不带到下一个包（2026-10-23 用户定）。资料只从“项目资料”取，成果放“成果输出”，过程文件放“工作文件”。

## 10 W5.5a 指标与估算速核（b 阶段）

在 05.9 比选前，每个方向一行：面积、容量、效率指标（如单车位面积）对照指标表目标行；再按单方造价经验值给估算区间，标 ◐。结果供 05.9 的“指标与效率”“投入与实施”两维使用。06.6 体量模型就是 W5.2 的 SU / Rhino 场景，不另做。

## 11 07 展示入口

07 不计入完成情况，只用来打开展示：07.1 文本展示（连续阅读，可导出 PDF），07.2 交互展示（主图、点位、说明联动，分析动效由 Claude 做）。主稿是交互页加 60–90 秒影片，PPT / PDF 只作导出备份。AI 效果图和 AI 视频只表达氛围，几何和分析以 SU / Rhino 同机位导出图为准。

**W7.1 出展示前的统一性校核**（a、b、c 都做）：
1. 每张图、每段文字都能对上至少一条策略 P（b 阶段前对上章末结论），没有孤立内容。
2. 没有和已确认结论冲突的说法；有冲突先改主线卡。
3. 功能色、流线色、术语与主线卡表达基准一致。
4. 数字全部来自同一张指标表。
5. ◐ 推断内容都已标注。

选入展示不等于发布或交付；未选内容保留。

## 12 08 交付与归档

**W8.1 交付清单与记录**（每个阶段结束）：交付什么（图纸、模型、文本、图像）· 各用哪一版 · 交给谁 · 什么时间 · 对方反馈。

**W8.2 归档与复盘**：资料、源文件和成果是否都在项目文件夹三区；然后列**方法沉淀清单**，由用户逐条定是否入库：
- 本项目补充项 S 是否收进方法库；
- 类型参考卡新增或修订（brief-and-metrics）；
- 分析图候选模板是否转正（如 B10–B12）、配色增补（architecture-analysis-diagrams）；
- 各 skill 用下来不顺的地方。
