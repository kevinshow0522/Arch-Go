# 概念方案推演（05 章）v0.1

本 skill 管 05 章怎么想、怎么推、怎么比：从上游章末结论提炼关键矛盾，提出多个方向，按步骤推体量，最后比选定向。图怎么画不在这里：B1 体量生成、B2 功能、B9 流线用 architecture-analysis-diagrams；效果图提示词用 GPT 效果图 skill。流程、交接、资料等级以主流程 skill 为准。

**核心是一条可追溯的链**：关键矛盾 C → 理念 → 策略 P → 每一步体量动作 → 比选。每个下游成果（图、文字、模型场景）都要能指回某条 P 和某条 C；指不回去的就是孤立内容，要么补上来源，要么删掉。

一个子对话只做一个包。方向可以有 3 个以上：W5.2 每个方向各开一个对话；W5.3、W5.4 在 b 阶段可以只给最有希望的 2–3 个方向做简版，其余方向只做到体量推演，照样进入 W5.5。W5.5 单独开短对话，只读已存成果，不读原始资料和聊天。

阶段：b 概念方案 05.1–05.5、05.7、05.9 为核心项；05.6、05.8 按需。a 项目策划只做 05.1 初步设想和 05.2/05.5 的容量试排。

## 开工

1. 读设计主线卡（若已有，注意版本号）、最近交接记录、本包要用的上游章末结论。
2. 判断建筑类型，读 brief-and-metrics 里对应的类型参考卡（容量口径、层高、坡道等）。
3. 读本地项目资料前先问用户。成果存“成果输出”，过程文件和脚本存“工作文件”。

## W5.1 设计主线

### 两种入口

- **正向推演**：上游 02.7、03.8、04.7 已有，按下面 1–5 步推。
- **逆向补卡**：项目中途进场、已有效果图或方案（如停车楼试点），从已有成果反推矛盾和策略。全部标 ◐，用户核对后才能当正本用；上游缺的章末结论在缺口表里列出。

### 步骤

1. **关键矛盾 C1–C5**：只从上游章末结论里取，每条写来源条目；最多 5 条，按重要性排序。没有来源的“矛盾”不收。
2. **方向**：针对排前两位的矛盾，提出 3 个以上有实质差异的空间主张。差异必须在布局、体量或剖面上；只换立面、只换材料不算一个方向。
3. **一句话理念**：每个方向各一句，说清楚“用什么空间做法回应哪条矛盾”，不写形容词口号。比选前各方向理念并存，比选后锁定一个。
4. **策略 P1–P5**：每条写成“动词＋对象＋结果”，例如“消防车库独立设置，直出南侧道路”。每条注明回应哪个 C、管哪些下游条目。下游成果只引用这些编号，不另换说法。
5. **不做什么、缺口与待定项**：照主线卡格式写。

### 主线卡模板（上半：设计主线）

标记：✔ 用户已确认 · ◐ 推断待核 · ○ 缺资料。卡片带版本号；改版须用户确认并写明改了哪条、为什么；改版后引用旧版的成果进入待复核。

1. 项目一句话
2. 服务阶段
3. 关键矛盾表：编号 / 矛盾 / 来源条目 / 状态
4. 方向与理念：方向 A/B/C… / 一句话理念 / 主要差异（布局、体量或剖面）
5. 核心策略表：编号 / 策略 / 回应 C / 管哪些条目 / 状态（多方向时注明属于哪个方向，共用的写“共用”）
6. 已定方向（05.9 后填）
7. 不做什么
8. 缺口与待定项：项 / 影响 / 需要什么资料

下半“表达基准”（配色、功能色、流线色、机位、术语、标注、版式）见 architecture-analysis-diagrams 与主流程 skill。

## W5.2 体量推演

### 步骤

| 步 | 做什么 | 谁做 | 出什么 |
| --- | --- | --- | --- |
| 0 容量试算 | 把任务书指标换成面积、层数、跨数。例：停车楼 车位数 ÷ 每层车位 → 层数，再定坡道形式（直坡道、螺旋、错层） | AI | 试算表 |
| 1 可建范围 | 红线、退线、限高拉出“能建的盒子” | AI 写脚本，用户运行 | 场景 01 |
| 2 容量体 | 按试算放入初始体块 | AI 写脚本 | 场景 02 |
| 3–5 策略动作 | 每步一个动作：切、退、抬、架、分、连、错层等 | AI 写步骤和脚本，用户调整 | 场景 03–05 |
| 6 剖面检查 | 层高、坡道、屋面和场地高差是否成立 | AI＋用户 | 1–2 个剖切示意 |
| 7 总平落位 | 体量回到总平，出入口和室外空间成形 | AI＋用户 | 总平草图 |

规则：

- **一步一个动作。** 每一步只做一个形体动作，写一句“因为 C#，所以做什么（P#），得到什么”。一个方向 4–6 步；超过 6 步说明动作太碎，合并。
- **步骤卡是文字正本。** SU/Rhino 场景和 B1 图都按步骤卡编号，三者一一对应。B1 是推演的副产品，不事后另编故事。
- **每一步都存成场景**，用同样两个机位导出：顶视（平行投影正上方）、分析（平行投影等轴）。图片尺寸固定。

### 推演步骤卡模板

| 步 | 动作 | 因为（C#） | 对应策略（P#） | 关键尺寸 | 得到什么 | 场景名 |
| --- | --- | --- | --- | --- | --- | --- |
| 03 | 北侧长立面后退 6 m | C3 对居住区压迫 | P3 | 退 6 m，高 18 m 不变 | 北侧留出绿化缓冲带 | A-03-退 |

### 建模分工：AI 建模，用户调整

| 环节 | AI 做 | 用户做 |
| --- | --- | --- |
| 推演步骤和尺寸 | 写步骤卡，每步给关键尺寸 | 改尺寸或否掉某一步 |
| SU 体块 | 写 SU Ruby 脚本，粘到 Ruby 控制台一键生成；每步一个图层（标记）和一个场景，场景名与步骤卡一致 | 运行脚本，手动调整 |
| Rhino 建模 | 曲面形体、参数化立面（如穿孔板图案）或要一次出很多方向变体时：写 RhinoPython 脚本或 Grasshopper 定义步骤，把层数、跨数、坡道形式、退台等做成参数，一组参数就是一个方向 | 运行脚本或调参数；用命名视图建同样两个机位导出，或导入 SU 统一出图 |
| 快速草模（可选） | 讨论阶段用浏览器 3D 草模给用户看几个方向的大关系 | 看完挑方向，正式模型仍在 SU/Rhino |
| 导出 | 给出导出清单 | 按清单导出，拖进对话 |
| 分析图 | 在导出图上画 B1、B2、B9 | 核对 |
| 效果图 | 写 GPT 效果图任务单，指定用哪张导出图做底 | 交给 GPT 出图并挑选 |

**SU 还是 Rhino**：方正体块和常规推演用 SU；曲面形体、参数化立面、要一次比较很多变体时用 Rhino＋Grasshopper。同一个方向只用一个软件的模型作正本，另一个只做辅助，避免两套模型对不上。两个软件的机位名称、视角和导出尺寸保持一致。

脚本要求：单位米；原点用项目原点（与地图面板一致）；脚本开头写明对应方向和步骤；每次改尺寸改脚本参数区，不在脚本中间散改；脚本存“工作文件/05/脚本”。

## W5.3 功能与流线

- 功能按楼层落位，面积回到 02.7 指标表核对。
- 出入口位置以 03 的四边界面表为依据，写明用的是哪条边、哪条依据。
- 流线分类别画（如车行、人行、消防、后勤），所有图同色同义；关键交叉点单独说明怎么避开。

## W5.4 立面、环境与重点空间

- 立面写“表情”而不是样式：朝哪个对象、要藏什么、要显什么，对应哪条 P。
- 05.6 只做建筑层面的被动策略（朝向、采光、遮阳、自然通风），不补结构、机电等其他专业内容。
- 效果图另建任务交给 GPT，不在本对话里等待。任务单写：方向、机位（指定导出图）、要表达的策略编号、材料与色彩、标注“意向”。

## W5.5 比选与定向（章末）

**第一关，门槛（不过就出局）**：指标达不到任务书；消防或规范有硬伤；违反规划条件（限高、退线、出入口）。

**第二关，6 个维度定性比较**，每格写 ●（好）◐（一般）○（弱）加一句理由，不算总分：

| 维度 | 看什么 |
| --- | --- |
| 1 回应关键矛盾 | 逐条看 C1–C5，权重最高 |
| 2 场地关系 | 是否用好了 03.8 的“可利用、要保留” |
| 3 使用与流线 | 好不好用，流线是否清楚 |
| 4 指标与效率 | 容量、面积效率（如停车楼看单车位面积） |
| 5 形象与城市界面 | 对街、对周边敏感对象、对景观面的表情 |
| 6 投入与实施 | 造价高低、施工难度、能否分期 |

### 比选表模板

| 维度 | 方向 A | 方向 B | 方向 C | … |
| --- | --- | --- | --- | --- |
| 门槛 | 通过 / 出局（原因） | | | |
| 1 回应关键矛盾 | ● 理由 | | | |
| … | | | | |

最后写：选定方向＋为什么＋从落选方向吸收什么。选定后主线卡升版为 v1，锁定理念和策略；其他方向存档，不删。甲方另有评价要求时，作为方案调整处理，不改本比选方法。

## 收尾

1. 成果存入项目服务，注明引用了主线卡哪一版、哪条策略（例如“主线卡 v0.1 · P1”）。
2. 写一条交接记录：本包做了什么、用了哪些场景和导出图、留下的待定项。
3. 用户的确认写成记录，不靠对话记忆。

## 不做什么

- 不为凑数加方向：方向之间没有实质差异就合并。
- 不在效果图上画分析，不拿效果图当几何依据。
- 不补结构体系等其他专业内容（框架范围只到建筑概念设计）。
- 不跳过门槛直接比好看。

## 出 07 展示前的统一性校核

1. 每张图、每段文字都能对上至少一条策略（P1–P5），没有孤立内容。
2. 没有和已确认结论冲突的说法；有冲突先走变更流程。
3. 功能色、流线色、术语和主线卡完全一致。
4. 数字（面积、容量）全部来自同一张指标表。
5. 推断内容都已标注，或已按总平面图核对过。

## 示例

停车楼试点（环科集团立体停车楼）的主线卡 v0.1 是逆向补卡的例子：矛盾 C1–C5、理念“一栋楼、一个棚、一座车库”、策略 P1–P5（三流分离、三体加一广场、两种立面表情、橙色导向、被动通风采光），全部 ◐ 待核。定稿后把主线卡和推演步骤卡放进本节。
