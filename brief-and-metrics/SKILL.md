## 资料与必问清单

- 每条事实带来源等级（A 正式文件 / B 甲方口头 / C 现场自测 / D 公开 / E AI 推断）和可信度（✔ ● ◐ ○，见主流程第 5 节）。E 级不能进指标表的目标行，只能进缺口表。
- 类型卡里的“必问清单”是核对用的：先对照项目资料和已知事实表，资料里有的直接填表并标来源；只把找不到的问题列成提问清单交给用户。不要把整份清单原样抛给用户。

## 项目指标表（02.3 的核心）

一个项目只有一张指标表，正本放项目服务（带版本，可导出 Excel）。所有图纸、分析图、汇报里的数字只从这张表取。

七列：指标 · 数值与单位 · 口径（计入什么、不计入什么）· 性质（甲方目标 / 规划硬性 / 规范下限 / 估算 / 设计结果）· 来源与等级 · 可信度（✔ ● ◐ ○）· 影响条目。

三层指标：
1. 通用层：用地面积、总建筑面积（分计容与不计容）、容积率、建筑密度、限高、绿地率、退线。
2. 类型层：从类型参考卡带入，使用卡里的统一叫法。
3. 项目层：AI 按项目新增，写明为什么需要。

规则：
- 02.3 只定口径和目标，不做排布。
- 05 排出的数字写回同一张表的“设计结果”行；06.8 拿目标行与结果行对比。
- 改口径要用户确认，并写明改了什么、为什么。
- 引用类型卡数值时注明卡的版本；没对照原文核过的规范数值一律标 ◐。
- 02.7 确认时，指标表的目标行必须有两类指标（2026-11-26，测试项目跑完后补）：容量类指标，和单位面积效率指标，按建筑类型取，例如停车楼是车位数和单车位建筑面积。没有的写进缺口表，并注明“05.9 的指标与估算速核只能对量级”，不拿估出来的数当目标。

## 立项测算表（02.5）

（2026-11-25 用户定）业主看重立项分析和立项阶段的经济测算，项目策划深度的 02.5 做成一张立项测算表，四块：

1. 投资估算：分项和合计，写清按什么口径估（单方造价、同类项目、甲方给的数）。
2. 资金与分期：钱从哪里来，分几期，各期做什么。
3. 收益或运营：有收益的项目写收入和运营成本的口径；没有收益的写运营方式和每年的运营开支。
4. 敏感性：挑一两项对结论影响最大的（如造价、规模、出租率），写它变动后结论怎么变。

规则：
- 每个数写来源和可信度（主流程第 5 节）。来自对标案例或经验值的估算标 ◐，写推断依据；来源里找不到的标 ○，进缺口表，不编数。
- 规模、面积、车位等数字只从项目指标表取；测算用到的新指标先进指标表。
- 测算只到立项判断够用的深度，不替代造价、财务专业的正式测算；需要时写成“专业接口”。

## 策划深度的对标案例

项目策划深度的对标并在 W2.1 里做，不另开 W4.1，给立项测算当依据：

- 按 case-study 的案例卡格式，只填规模（04.3）、投资和运营（04.6）三栏，再加基本信息、来源与等级；平面、剖面、形态材料不做。
- 检索顺序、案例等级、不凑数的规则照 case-study；AI 不凭记忆写案例的规模、投资和运营数字，来源里找不到就空着。
- 最后写一段对标结论（简版 04.7）：本项目的规模、投资、运营口径参照了哪些案例，差别在哪，哪些数只能当区间用。

## 设计任务书（02.7）

固定五段：功能构成与关系 · 规模与指标（引用指标表版本；目标行要有容量类指标和单位面积效率指标，缺的列进待定项）· 标准与品质要求 · 投入、分期与运营 · 待定项（每项写影响哪个条目、找谁定）。结尾列出给 05 的约束与矛盾候选（编号 C02-n，从类型卡“常见矛盾”对照本项目挑选；05.1 定稿主线卡时再并成 C1–C5）。章末结论只读已存成果，不读原始资料和聊天。

## 类型参考卡

一类一张，跨项目复用，带版本。规范数值以用户本地“建筑设计专家库”为准（F:\0设计项目\0设计资料及参考\建筑设计专家库），每个规范数值注明出自哪一条。云端连不上用户电脑时，由用户上传相关规范，或在本机 Code 模式里核对；用户说明不必参考的规范，相关数值按经验值使用。只收会改变体量与总平的数值，不做规范审查。

每张卡八段：适用范围 · 规模经验值 · 尺寸与模数 · 规范要点 · 功能关系 · 常见矛盾（给 05.1）· 必问清单（按“不问就没法开始”排序）· 来源与版本。

现有与计划：停车楼 v0.2（下附）；办公楼、学校、办公室内待起草（办公室内属改造类：场地研究换成现状踏勘，不写规划条件，改写人均面积、工位与会议配比、净高与吊顶）。之后按实际项目积累。
