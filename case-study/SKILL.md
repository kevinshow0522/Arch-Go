# 案例研究（04 章）v0.1

本 skill 管建筑项目的案例研究：借鉴什么问题、去哪找、资料够不够、怎么写成能给 05 用的结论。流程、交接、事实来源等级 A–E 以主流程 skill 为准。

**先问题，后案例。** 案例数量由借鉴问题决定，不设下限，也没有固定数量。没有合适案例是正常结果，写明原因即可，这一章不算缺项。

## 何时用

| 工作包 | 条目 | 输入 | 输出 |
| --- | --- | --- | --- |
| W4.1 借鉴问题与检索 | 04.1 | 设计主线卡的关键矛盾、02.7、03.8 | 借鉴问题 Q1–Qn、检索记录表、入选参考清单（带案例等级） |
| W4.2 案例拆解 | 04.2–04.6 | W4.1 的入选清单、案例资料 | 每个案例一张案例卡；一个子对话做 1–2 张 |
| W4.3 借鉴结论（章末） | 04.7 | 已存的案例卡 | 借鉴结论表、权衡项、展示选择，等用户确认 |

一个子对话只做一个包。阶段：b 概念方案 04.1 为核心项，04.2–04.7 按资料情况做；a 项目策划只在需要定位或运营参考时做 04.1 和简版 04.7；c 方案设计只为细部问题补查。全部借鉴问题都没有合适参考时，04.1 和 04.7 合并成一个简版，04.2–04.6 显示“不适用”。

## 开工

1. 读设计主线卡（关键矛盾 C 编号、策略 P 编号）、最近交接记录、02.7 任务书和 03.8（若已有）。
2. 判断建筑类型，读 brief-and-metrics 里对应的类型参考卡。
3. 读本地项目资料或用户资料库前先问用户（每次都问）。

## 借鉴问题（W4.1 第一步）

- 从主线卡的关键矛盾和 03.8 的启示写出 Q1–Qn，一般 3–5 个。每个 Q 是一个设计要解决的问题，例如“消防车库和社会停车共用场地时，出车线怎么不被堵”，不写“找几个好看的停车楼”。
- 每个 Q 注明来自哪条矛盾（C 编号）、可能影响哪条策略（P 编号），以及回答它至少需要什么案例等级：要看平面、剖面、流线就要 A；看立面材料 B 就够；问题本身是技术原理的，直接查原理资料。
- 参考分三类：同类案例（同类型、相近规模）、跨类型类比（类型不同但解决同样的问题）、原理与图集。同类找不到时先找跨类型，再找原理。

## 检索顺序

按顺序查，前一层能回答问题就不往下翻：

1. 用户的资料库（参考优秀文本、过往项目、甲方给的参考）：用户提供或拖进对话。
2. 中文平台：谷德 gooood、ArchDaily 中国、有方、建筑学报等期刊。
3. 外文平台：ArchDaily、Divisare、事务所官网。
4. 规划公示、新闻报道：补规模、投资、建设和运营情况。
5. 规范、图集、设计原理：没有合适案例时的替代来源；条文以用户手里的正式版为准。

规则：
- 每个参考都要留可点开的链接或文件位置。AI 不凭记忆写案例的规模、车位数、面积、年份；来源里找不到就空着。
- 图片只引用链接并注明来源，不存副本；展示要用时再确认版权。
- GPT 和 Claude 都能检索，谁接到 W4.1 谁查，用同一张检索记录表。

## 案例等级

案例等级说的是这个案例的资料够研究到哪一步，和主流程里单条事实的来源等级 A–E 是两回事：案例卡里的每个数字仍要标来源等级。

| 等级 | 门槛 | 能写的条目 | 不能做的事 |
| --- | --- | --- | --- |
| A | 至少有平面和剖面（或总平），加 1 项可核对的数据（面积、车位数等） | 04.2–04.6 全部 | — |
| B | 有实景照片，加建筑师、地点、年份 | 04.5 形态材料；04.2、04.6 只写观察到的 | 不做平剖分析，不引用规模数据 |
| C | 只有文字报道或二手转载 | 只进检索记录，作线索 | 不单独开卡，不下结论 |
| 原理 | 规范、图集、教科书 | 写进 04.7 的成立条件 | 不当作案例 |

降级规则：数据在来源里找不到，或只有二手转载，按低一级算。等级后面标“已核对 / 未核对”；AI 只能标“未核对”，用户看过或有原始文件才标“已核对”。

## 不凑数：停止规则

1. **入选门槛**：案例要同时满足能回答至少 1 个 Q、案例等级够回答这个 Q。造型好看、名气大都不算理由。
2. **达标即停**：每个 Q 找到 1 个够等级的参考就可以停，最多留 3 个；一个案例可以同时回答几个 Q。
3. **查过留痕**：每个 Q 最多查 3 个渠道，每个 Q 写一行检索记录。
4. **找不到就写不适用**：查完 3 个渠道仍没有够等级的参考，就改用原理资料，或者写“无合适参考”。
5. **展示不设下限**：04.7 按最能说明问题的标准挑展示卡，0 张也可以。

检索记录表（每个 Q 一行）：

| Q | 渠道 | 关键词 | 入选 | 淘汰及原因 | 结果 |
| --- | --- | --- | --- | --- | --- |
| Q1 | | | | | 已找到 / 改用原理 / 无合适参考 |

## 案例卡（W4.2）

一个案例一张卡，固定 7 栏。第 4 栏只写等级允许的条目，其余写“资料不足，不分析”。

| 栏 | 内容 | 写法 |
| --- | --- | --- |
| 1 基本信息 | 名称、地点、建筑师、年份、规模 | 规模只写来源里有的，没有就空着 |
| 2 来源与等级 | 链接或文件位置、案例等级、已核对 / 未核对 | 至少 1 个可点开的来源 |
| 3 回答哪个问题 | Q 编号，及对应的 C 编号 | 对不上任何 Q 的案例不开卡 |
| 4 研究条目 | 04.2–04.6 中等级允许的几项 | 每项 2–4 句，配 1 张引用图或自绘简图 |
| 5 可借鉴的做法 | 1–3 条，每条一句话 | 写“做法”，不写“风格” |
| 6 成立条件与项目差异 | 这个做法靠什么条件成立；本项目有没有这个条件 | 给 04.7 直接用 |
| 7 不能下结论的地方 | 资料缺什么、哪些是推断 | 没有就写“无” |

需要分析简图时，画法用 architecture-analysis-diagrams；配色跟本项目统一。

## 04.7 借鉴结论（W4.3）

在单独的短对话里做，只读已存案例卡的第 3、5、6 栏，不读原始资料和聊天。

成果：
- **借鉴结论表**：问题 · 可借鉴做法 · 成立条件 · 本项目是否具备 · 来自哪张卡。
- **权衡项**：做法之间互相冲突，或超出经济条件时，单独列出。写清是哪几个方面互相冲突、各自的代价（含造价高低），供建筑师在 05 里取舍。设计常常只能顾及几个方面，不要求面面俱到；04 不替 05 做选择。
- **无合适参考的问题**：列出 Q 编号、查过的渠道和改用的原理资料。
- **展示选择**：需要展示时选哪几张卡，说明理由。

规则：
- 每条结论都能追到案例卡；追不到的不写。
- 04.7 不提方案，只写做法、条件和差异。
- 用户确认后才算完成；确认后结论和权衡项写进设计主线卡，供 05.1 引用。

## 结束

成果存入项目服务，注明引用的主线卡版本；写一条交接记录（做了哪些条目、Q 编号与检索结果、案例卡编号、待核对项、下一包）。
