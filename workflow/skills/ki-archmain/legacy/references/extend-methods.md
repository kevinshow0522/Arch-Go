# 接入更详细的子项设计流程

当用户深化工作流章节、提供详细流程文档或要求丰富方法时读取。基础框架从原有四份设计文档扩展；已深化范围以主入口的方法版本和工作区续接卡为准，不推断已包含用户未提供的独有操作细节。

## 工作流建设的续接与同步

先读取工作区入口指定的续接卡，定位当前章节、最新稿、用户确认依据和下一动作，再按需读取正文。卡只保存状态与文件入口，方法正文保留一个正式维护位置；工作区没有卡时，先查已有章节索引和直接相关文件。

用户要求先内容后表达时，分别记录内容、表达方法和界面实现的状态。内容稿生成后保持草案；用户确认或明确要求同步的范围纳入对应方法，其他章节和未讨论的表达形式不随之确认为完成。

同步顺序：保留来源草案→更新对应方法及必要索引→核对来源、限制与链接→同步用户指定的安装目标→比对文件版本与哈希→记录实际检查结果。仅改源包不声称安装版已更新；本地安装不等于其他宿主已同步。

结束前更新当前章节、内容与表达状态、正式方法版本、同步目标、未决事项、下一步和准确文件入口。复用已有成果，只重读或复核受本次变化影响的部分；用户明确的新要求优先于旧续接点。

## 先区分方法与项目资料

- 可跨项目复用的判断和步骤：进入对应阶段/专题参考。
- 某项目的目标、尺寸、预算、甲方决定、进度：进入该项目记录。
- 特定软件操作：作为条件触发的专门方法/脚本，注明软件和版本；没有验证不宣称可执行。

## 每个详细子项方法的结构

采用稳定方法编号（例如M06-FACADE）和独立标题；记录版本与来源。正文包含：

1. 适用问题与不适用边界。
2. 输入及来源/精度要求；缺失时哪些可先做、哪些受阻。
3. 执行步骤及分支判断，每步指向有用的设计输出。
4. 与共享条件、其他子项及专业接口的依赖。
5. 完成依据、实际检查方式和未验证事项。
6. 输出与记录位置、续接入口、变更触发条件。

步骤过长时按独立设计问题再拆文件，阶段文件保留短索引和读取条件。不要把每个文件都设为默认必读；不要为了方法目录完整生成未获授权的项目任务。

## 导入步骤

读原文→提取目录与稳定编号→标来源位置→区分原有明确要求和AI扩展建议→按设计问题拆分→检查前后依赖→用实际任务例子验证能找到正确方法。保留源文档；不能用过短摘要悄悄删掉关键技术检查或例外条件。

例如“只调整入口雨棚”：应定位入口子项和当前版本，读取相关立面/模型方法及约束，执行局部工作；不要求重新做项目机会、定位和完整案例研究。例子用于检查路由，不向真实项目添加样例数据。

若用户改变公共方法，明确修改该方法版本；正在进行的项目是否迁移采用新方法应按影响判断并记录，不无痕改写既有确认决定。
