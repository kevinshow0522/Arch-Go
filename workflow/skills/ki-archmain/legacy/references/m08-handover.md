# M08 交付与归档

> 本机模型交付入口（2026-10-27）：08按[建模章节接口](../../references/sketchup-modeling-entry.md)核实际SKP、图件、资源、版本及可编辑范围，关联真实已做检查；不自动新建模型或将工具finished当成用户设计确认。

方法版本：1.18｜内容框架V0.4｜2026-10-15。08管理本次成果清单、真实交付记录和可恢复归档；可服务个人学习、内部讨论、阶段沟通或对外交付。当前服务深度的核心和按需要求见[现行阶段与核心项](../../SKILL.md#2-八章与服务阶段)。

## 08.1 交付成果清单

### 范围与版本

沿委托和本次用途列出应有成果、实际文件、源版本、检查、未决事项与访问入口；设计内容归01—06，07只选取其中实际成果展示。清单区分工作稿、用户确认、专业确认与拟交付版本，缺失不能由目录标题或文件数量补足。

本轮涉及设计变更时，引用[调用与衔接](workflow-coordination.md)及其配套记录，核对已关闭范围、有效版本和遗留项；整次变更完成与本章实际交付、归档分别记录，专业检查证据保留原入口。

### 文件与实际检查

使用项目storage：长期资料归materials_directory，过程与模型证据归working_directory，最终文件归output_directory。核可编辑源、必要资源和同源阅读文件；临时输出复制到项目成果目录后核实际文件与哈希，再按服务schema登记。文字保存检查file_export.saved，数据库与文件落盘分别判断。

图纸模型按同版对象、单位、坐标、尺寸与索引核对；文档、表格、PPT及交互页面按实际格式检查阅读、计算、裁切和打开。模型保存重开、可编辑性与专业内容分别核验，未做项保持未验证，不把截图或ZIP存在当完成。

## 08.2 交付记录

记录真实发生的交付：时间、接收对象、用途、方式、版本、实际清单、发送/发布回执及反馈。仅选入07、生成文件或提出发送计划时，状态保持待交付；本项不因本轮方法更新自动完成。

外部发送、发布和跨对话消息按用户明确授权执行。获得反馈后关联原版本，记录接受、需调整和待确认事项；形成实质设计变化时回到负责任务并保存新成果，不覆盖原交付历史。未收到反馈不推定对方认可。

## 08.3 项目归档与复盘

把有效项目依据、决定、源图模、最终文件、检查、交付记录、遗留问题和下一动作关联起来，记录方法/框架版本与执行者。保留用户手改、旧版本及必要资源，用实际打开或相称恢复检查确认下次可以接续。

模型文件、工具受管状态和业务任务记录分别留可回查入口；不能只复制SKP就声称另一台电脑能恢复受管任务。归档不擅自删除过程文件或移动原目录。复盘只提炼有实际结果支持的通用经验，项目事实仍留项目；后续修改另建可追踪修订，条件变化先判断影响。

1.18起，本章在当前阶段有核心项（如08.1）时，08.3必须做，可以是简版：a、b阶段的简版只归档本阶段交付文件、版本与要点，完整复盘在c阶段或项目收尾时进行。

## 沿用的成果支撑方法

任意阶段需要学习整理、沟通、决策或交付时调用。模型、图纸、判断、计算底稿、图像、网页、PPT或ID均可成为成果；不默认每次生成汇报。

| 子项 | 执行流程 | 成果与核查 |
| --- | --- | --- |
| 成果用途与范围 | 沿用个人学习、内部讨论或对外沟通等实际用途→核对选中成果→选择形式及深度→核对现有约定 | 本次选中范围；内部草稿、用户确认与正式交付分开 |
| 源成果整理 | 按稳定标识与版本查当前图模/指标/结论→标历史和待复核→补齐出处 | 成果清单；不混合未协调版本 |
| 图纸模型输出 | 核对输入版本、图层/对象、单位和必要注释→生成约定格式→实际打开检查 | 可编辑文件及阅读文件；文件生成不等于专业审查 |
| 分析图与图像 | 明确每图论点→选对应证据/视角→统一标识与图例→检查可读性 | 有设计作用的图；示意、模拟、实测分别标明 |
| 汇报叙事与版面 | 围绕待决定事项组织依据、比较和建议→选图与必要数据→生成→逐页检查 | 缺图、裁切、溢出、字体与版本检查；不重复堆背景 |
| 交付记录与续接 | 登记文件路径/版本/用途→保留可编辑源与已做检查→说明未决事项及维护责任 | 可恢复的交接记录；发送/发布仅按实际授权执行 |

## 多子项整合与交付核对

先核对共享指标与总图，再核对各子项引用的确认条件和成果修订。不同子项完成深度不同，应明确说明，不用统一封面掩盖差异。汇报输出中的实质修改要回写相应源成果与决定，保留用户手动编辑，不能让PPT成为无记录的第二套事实。

校核顺序按风险：错误项目/版本→关键指标与结论→缺失与专业接口→阅读布局→文件访问。发现设计依据变化时回到负责子项修订，再更新受影响输出。

交付完成记录必须回答：交付了什么、用哪版来源、检查过什么、还未验证什么、下次从哪里继续。不要因输出文件数量足够就标整个项目完成。
