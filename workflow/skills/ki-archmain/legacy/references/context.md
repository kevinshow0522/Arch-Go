# 详细流程与上下文管理

Skill 文件集合是外部方法库，不是无限上下文，也不是项目记忆数据库。通常先提供名称/描述，选中后读主文件，相关参考文件再按需读取。已读内容、聊天、图片和工具结果共同占用模型当前上下文；容量依所选模型和产品而变，不承诺一个通用 token 数字。

## 一次任务的最小工作集合

1. 用户当前要求与授权、项目身份和本次子项/对象。
2. 最新共享硬约束、相关已确认决定和未解决冲突。
3. 当前任务的续接卡、输入版本、成果版本和依赖任务状态。
4. 解决当前问题需要的一个或少数方法文件。
5. 直接支持判断的资料段落、图纸或模型对象；保留可回读入口。

这是选择策略，不是固定文件数上限。跨阶段问题确实需要多个方法时读多个；不为了节省上下文漏掉关键约束，也不因文件存在就全部加载。

## 逐层读取

- 续接项目时另查一次 `kg_list_records(kind="note")`，打开标题以“变更｜”开头且状态为active的变更主记录；note不随 `kg_get_context` 返回。
- 先项目摘要，再子项、任务；再读取具体来源。已有对象标识时优先准确定位，不跨所有项目全文搜索。
- 初次可用 `kg_get_context(max_chars=12000)` 获取概要；`max_chars` 是 JSON 序列化字符预算，不是 token 上限，也不是总上下文容量。
- `ready=false`、`next_offset`、`indexes_partial` 或 `material_index_partial` 表示存在未读部分。顺着返回的工具/偏移补读与决策相关的内容；需要完整清单时翻完索引。
- 原文按固定 version、成果按固定 revision 分页，避免读取期间改版而拼接不同内容。不能凭前一页宣布读完。
- 文件型大流程先读目录/条目索引，再打开目标小节。每个方法保留标题、触发词、输入、执行、检查和关联入口，不能切成丢失限制条件的碎片。

## 任务结束或切换前保存

将已确认事实/决定写入相应记录；将成果写入版本库；续接卡保留实际完成、已做检查、当前依据与版本、未决问题、下一步和需要读取的入口。项目总摘要只更新影响下一次工作判断的变化，不在每个微小动作后改写。

换对话后重新读取最新项目记录和相关方法；不要依赖旧聊天自动带入全部原文。上下文压缩后的摘要是检索线索，关键尺寸、版本、用户决定和引用必须可回读。没有服务时保留用户可访问的交接文件并标“未同步”，不能声称已保存到项目库。

跨专业交接或设计变更按[调用与衔接](workflow-coordination.md)及[配套记录](../assets/design-change-record.md)保存目标、来源、返回和影响回查。一项变更一份记录，引用已有条件、决定、成果及检查入口，不重复维护另一套事实。普通咨询和学习不强制套用变更模板；主记录与项目服务的对应按[项目服务](project-service.md)办理。

## 大规模方法库

内容章节下继续增加独立子项文件与短索引即可；模块变大时按设计问题拆分，主 Skill 保持短。具体项目的详细设计流程留在项目资料/任务中；可以复用的通用方法才加入 Skill。入口指向正确模块、模块引用正确来源、项目状态可续接，比一次塞入全部材料更重要。

官方文档提到的初始技能目录预算仅用于技能名称/描述的发现列表，不是整个 Skill 正文或参考资料的统一大小上限。不要把字符数当作 token 数，也不要把本地文件存储能力说成模型能够同时记住所有内容。
