# 跨Skill调用、交接与变更回查

方法版本：1.19，1.20修订｜2026-10-16。跨专业制作、图模不一致、依据变化或成果交接时按需读取；普通咨询、学习或无关联影响的单项工作不强制填写变更记录。沿用1.18的项目目录、V0.4八章及0/a/b/c深度，不增加设计条目或另一套任务状态。

KI负责判断目标、组织依赖、指定控制来源并统一接收；专业Skill负责其适用范围内的执行、自查与返回。专业检查仍以对应方法为准。一项设计变更使用一份[配套记录](../assets/design-change-record.md)，各任务引用同一来源和问题编号；不同变更分别记录并相互关联。AI从已有材料填写，用户无需另填表。记录落盘与服务保存见[项目服务](project-service.md)。

## 一、判断当前任务

同时核对用户当前意图、有效决定与成果状态、会改变结论的缺项。用一句话说明“本次处理哪个方案的哪个对象、要解决什么、做到什么深度、现在先做什么及理由”。

| 当前意图与状态 | 下一动作及边界 |
| --- | --- |
| 比较方向，尚未采纳 | 保留有效基线，生成注明假设的候选和比较；候选不自动成为控制版 |
| 已采纳变化，需要落实 | 先核决定的适用条件；可能推翻设计的缺项先处理，再按有效依据更新 |
| 图模、数字或结论不一致 | 定位同一方案、对象、属性及版本，依第四部分判断差异，再确定修改对象 |
| 只做核验或表达 | 核验返回证据；表达沿用有效设计。发现设计问题返回原判断环节，不暗改设计事实 |

一个任务可包含多种工作性质，但前期判断、候选制作和最终成果的有效状态分别标明。最终成果必须引用另一任务的控制版时，单独建任务，并在建任务时写入对该任务的依赖（服务只在建任务时接受依赖）；候选分析另建或先行。已具备的可靠成果优先核读沿用；不因进入深化或建模就重做全部上游研究。

## 二、选择Skill与安排先后

按当前问题、输入、必须返回的成果及检查需求，选择最少且足够的能力。先确认Skill适用范围、当前工具和真实文件可用；名称、安装或接口回应不能证明本轮能完成专业操作。

| 需要解决的问题 | 按需入口及范围 |
| --- | --- |
| 建筑分析、取舍或专业依据 | 对应M01—M06方法；需要知识依据时读取[建筑知识应用与来源](architectural-review-basis.md)，按需使用architecture-expert-library。知识引用不替代项目专业核验 |
| 场地矢量、影像及配准底稿 | map2model；交接时写明：交付目录为project.storage的output_directory下子目录，工作目录为working_directory/〈任务ID〉/map2model（在交付目录之外）；以用户要求的形式写“保留可重跑归档：源哈希、配准变换、检查结果、原图叠合”；清理只限该工作目录内已列清单的文件。其默认的桌面交付、Codex工作区与收尾清理不用于KI任务；能否接受指定工作目录以实测为准 |
| 可编辑建筑模型或既有模型修改 | professional-sketchup-modeling或blender-modeling，按模型类型和实际软件选择；共用[图模核验](modeling-verification.md)。当前SketchUp Skill只能定向修改其受管项目：用户自有的普通SKP先只读审计并交修改依据，或经授权在受管项目内重建目标对象，不新建重叠副本冒充修改；Blender导入与修改链另核 |
| CAD图纸及图模修订 | 对应M06与当前CAD工具；interior-construction-drawings只适用于内装，完整建筑CAD方法缺口应明列，不能据工具数量推定具备。没有可执行的CAD能力时可由用户主办（tags写`执行:用户`），KI交修改依据，用户按第三部分交回 |
| 分析图、图文或动画 | 先作对应专题判断，再按[表达方法](expression-interface.md)制作；Claude承担既定分析图和交互动效，GPT承担图片生成。各专题计算链按实际能力验证 |
| 展示、文件及交付 | M07、M08与实际文档、表格或演示Skill；生成、检查和实际交付分别记录 |

外部Skill按当前可用名称与入口定位，不依赖固定安装路径；专业包不必反向连接KI项目库。Skill或工具不可用时，继续有依据且不受阻的工作，明确待接手部分及下一入口，不把替代文件称作原定成果完成。

顺序由信息依赖决定：会改变定位、尺寸或设计结论的关键条件先核；资料整理、底稿核读、对象审计和影响清单可并行。候选分析可用于检验设计条件，最终分析图再引用有效控制版，避免让前期分析也等待其要协助确定的设计。共同输入有效后，不同文件的模型、分析及相关输出按各自依赖并行。建任务的顺序也随依赖：上游先建；下游的最终成果在上游接近有效版时再建，避免上游每存一版草稿都使其进入待复核。

同一文件或共享对象只设一名写入主办，其他任务返回修改依据，在明确交接点接续；并行任务开工及交回时核对共同输入版本。输入发生变化，只暂停或重查受影响部分。跨对话转交沿既定分工及用户授权，填写交接记录不等于另一端已启动。

## 三、交接什么、返回什么

共同输入包括：项目与任务身份、方案/对象/属性、当前工作性质、有效决定与来源版本、目标及保护范围、单位/坐标/定位点/标高/精度、必须成果、关键前置条件和未决编号。工作与输出位置使用真实project.storage；项目/任务ID与软件文档、工作单元和原操作回执分别关联。

| 接收方 | 共同输入之外需要收到 | 返回成果与专业检查重点 |
| --- | --- | --- |
| CAD | 有效底图、图号/图层/对象定位、应改尺寸与图纸范围 | 可编辑图纸、必要阅读图、原→新版本及修改位置；几何量测、标注与图面、保留对象、保存读回记录 |
| 建模 | 控制几何、对象及共享实例范围、应改或核对沿用的内容 | 可编辑模型或核对后沿用版、必要视图；定位与构件关系、共享实例作用域、实际视图、保存重开或相称读回及恢复入口 |
| 分析图 | 本图要回答的问题、场地或专题证据、方案状态、计算口径与允许的表达简化 | 可编辑分析源、必要静态/交互输出、结论及来源；路径/量算/专业依据、图文一致与实际阅读检查，模拟能力另核 |

每个接收方交回实际输入和输出版本、已做动作、检查对象/方法/结果/证据入口、保留范围核对、未执行项和未决事项。没有发生的检查不得预填通过。已有成果满足本轮有效依据时，返回核对后沿用及证据，不为了表示工作量制造新版本或重复移动对象。

专业主办对本专业返回负责；KI再核跨成果的对象、版本、几何、数字与结论。两者引用同一证据，检查范围分别记录；专业返回完成不能代替整次变更关闭。软件执行结果不明时先读原回执；已提交而取证失败时补取证，避免重复执行。

## 四、确定控制来源并处理冲突

按“方案＋对象＋具体属性”指定控制来源及其适用版本，不能只写“以CAD为准”“以模型为准”或“取最新文件”。入口平面定位可由有效CAD控制，复杂曲面可由模型控制，现状高差须有可靠测绘依据；不同属性可由不同来源控制，但共同坐标与对象关系必须成立。

文字决定可规定目标；相应几何尚未落实或核验时明确待核，不能把目标当成已完成图纸。候选模型、分析箭头、截图和表达简化不自动改写有效设计。

来源记录与图面图例使用同一套状态，图面不另起一套：

| 来源状态（记录） | 图面图例 | 含义 |
| --- | --- | --- |
| 有效 | 现状事实／已采纳方案 | 可靠现状依据，或已采纳并落实到控制源的设计 |
| 目标待落实 | 已采纳（待落实） | 文字决定已定，几何尚未落实或核验 |
| 候选 | 拟议 | 比较或推演中，未采纳 |
| 基线 | 现状事实／原方案 | 本次变更前的有效版本，被替代前仍有效 |
| 旧版 | 不上图，必要时标“历史” | 已被替代，只用于追溯 |
| 待复核 | 待核 | 依据失效或尚未核实 |

分析推断另标“推断”，不等同任何来源状态。条目状态（已确认、有成果、外部已有等）与第五部分的处理结论是另外两层记录，不用作图面图例。

差异先判断原因，再更新：

- 旧版残留：按仍有效的控制依据更新旧引用。
- 单位、坐标、对象映射等转换错误：修正转换并读回相关几何，不改变设计决定。
- 表达简化：确认简化不改变对象关系或结论，注明精度；误导判断时修正图面。
- 新设计提议：保留为候选，核影响与必要取舍；采纳后将决定落实到控制源，再更新下游。普通授权内的局部落实直接推进，涉及关键设计取舍时回到用户讨论。

来源本身有冲突或决定适用条件失效时，保留未受影响且仍有效的范围，失效部分标为待复核并记录待裁定项，推进不受影响部分。调整控制来源必须保留旧→新来源、所控属性、适用方案/版本、理由及核对依据；等值转换与切换软件不新增设计权限。来源变化后重新核受影响输入和检查，不能沿用过期的通过记录。

## 五、回查影响与关闭本次变更

从两条路径查找：一是记录、文件、图号及展示中的显式引用；二是建筑关系，如入口相连的路径、平台、立剖面、门窗、节点、数量、指标与相关专业接口。对象名称未出现也可能受影响。按实际问题追查到相关成果和结论，新增影响补入原记录；不预建整套专业任务，也不凭没有搜索结果认定无影响。

逐项记处理结论：需要更新、已改待核、核对后可沿用、更新并核对通过、等待条件。可沿用包括未受影响，或虽受影响但既有内容已经符合本轮有效依据，两种均需版本、理由与证据。未决事项只登记一次，编号写成“〈变更标识〉-Q1”（如E01-Q1），与成果questions中按顺序计的Q号区分，写入成果questions时文字以同一编号开头；说明影响、主办、恢复条件以及是否阻止本轮完成；关键缺项不能通过移出范围消失。这些是记录内的处理结论，不直接作为项目服务状态枚举。

只有以下条件均满足，KI才可记录本次变更完成：

1. 控制依据有效，关键取舍及适用条件达到本阶段要求。
2. 本轮范围及回查发现的相关项均已更新并核对，或有证据可沿用。
3. 不存在阻止本轮完成的未决问题；后续深化事项有责任和续接条件。
4. 当前成果的对象、图模几何、数字与结论相互一致，保护范围已核对。
5. 所需可编辑源、阅读文件、检查证据与续接记录已实际保存并核对，能够继续工作。

只完成部分时说明已通过范围，整次变更保持未完成。局部任务完成、整次变更完成、用户/专业认可和[M08实际交付](m08-handover.md)分别记录。完成后出现新条件，按影响重开相关项并保留旧版。此规则用于组织执行，不表示依赖自动发现、跨软件同步、跨宿主启动或记录自动写回已实现。
