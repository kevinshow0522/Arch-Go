# V0.6 独立空间生成行为验收
日期：2026-10-10。范围：一次自然入口、小样本、非双盲概念演练。

## 结论先行
**经一次公开保留的修正，主案的空间生成链条和本次范围内平面—剖面—体量几何一致性通过。首版不是全部通过。**

新入口真实推动了“作出新方案”而不是只交资料清单或评审模板。独立生成端在没有验收清单提示的情况下，形成主案、同面积且组织不同的备选、统一坐标底稿，以及实际平面、关键剖面、轴测。可观察能力比 V0.5 的文本局部演练更完整，但这不是受控模型能力增益实验。

未验证：高质量建筑表现、与崔愷本人或团队作品的审美相似度、跨多题稳定性、真实项目可建性。没有建筑师盲评、本人一致率或正式 UIA 委托。

## 1. 测试安排与防提示泄漏
- 候选编辑者、独立生成端、外部核查者分工。
- 独立生成测试只接收自然题“请用这个 Skill 设计 UIA 北京永久会址概念，指标暂未知，可合理假设”，既有未知场地背景、稳定 Skill 路径，以及自然交付要求：概念说明、平面关系图、关键剖面关系图、简易体量轴测。
- 未给生成端主备、路线、跨图、结构或越界验收清单。生成端自行按 Skill 执行。图像交付要求是任务输入，不应宣称技能自行决定出三图。
- 外部核查者在生成开始后完整读取 SKILL、生成模式、跨图规则、理论生成判断、图纸阅读卡和空间简报；初读路径与 SHA-256 见 read_log.json。
- 首版问题被发现后，外部核查者要求保留首版并只修问题，不追加风格或空间方案指导。

## 2. 可见的新设计及实质替代
主案“河岸公共厅”：西侧两层公共翼 B1、北侧连续大会堂 B2、东侧三层会议办公翼 B3，以单层冬季门厅 B4 连接。地面公众由东南假设入口到开放论坛，经 B1 局部穿堂到河侧。公众不以通过会议管理线为前提。冬季活动退回室内门厅，不把室外论坛全年舒适当作既成事实。

备选为紧凑叠层：72×54m 概念基底、最高 19.2m、沿西侧外部绕行，公共功能部分上楼；以更少占地/更集中维护换取更多竖向转换及更高体量。主备室内面积均为 10,080㎡，不是单纯换立面。备选尚未独立画三图，因此本次跨图结论仅对主案。

可辨的机制来源是“城市通路先于实体排布”“连续大空间与低尺度边缘并存”“少量局部跨越代替全部架空”。图纸/理论卡用于推进空间取舍，不直接照搬七院、菱形大屋盖或伪造工业遗存；这支持生成导向，不能据此认定作品气质已拟合。

## 3. 实际图面核查
外部核查者实际打开六张 PNG：v1 首版三图及 v1.1 修正版三图，均非只读提示词或源码。

- 朝向与体量：B1 西、B2 北、B3 东、B4 中间连接，平面与轴测对应。
- 层数与高度：B1 两层/9.6m，B2 大厅屋顶12m，B3 三层/14.4m，B4 单层/4.8m，图面和统一底稿一致。
- 公众路线：P0 橙线通过 B1 首层 y=108–120m 的局部穿堂；其余公众段位于地面开放空间。独立采样检查未发现 P0 穿过封闭地面实体。
- 管理及服务：会议管理线在 B4/B2 交界，办公管理线在 B4/B3 交界；两者未切断 P0。员工/货运从北东侧到达各目的块，不借公众线穿入受控核心。这里只检查概念邻接，不等于门禁、货车转弯或消防设计通过。
- A—A：x=84m，向西看，依次经过论坛、低门厅、大会堂。地面统一为假设±0.00，未伪造防洪抬高。
- B—B：沿公众穿堂补剖，表明二层在局部跨越，首层路径连续；支承位于剖面后方的说明避免把无柱剖切误读成悬浮。
- 结构：B2 36m 南北概念钢桁架、两端落点及1.8m屋盖结构带明确可见。B1穿堂跨越12m及支承方向有标注；B4为12m跨度低门厅。没有结构计算，不能认定这些跨度或截面已获工程验证。
- 图面为概念关系而非详细平面：外墙线及门禁线不全做门扇开口表达；A—A的橙箭头为公共节点/路径投影式表达，不表示P0全长严格位于剖切平面。精细深化时应提高表达精度。
- 所有尺寸、地块、标高、容量有假设提示；首钢桥/永定河只作方向示意，不冒称准确线位。

## 4. 必须保留的首版失败与修正
v1/render-r00：开放论坛 C1 的矩形角 (120,88) 越出生成端自设三角边界；该边界 x≤1.3y，故该点不满足边界。生成端初次程序检查覆盖建筑块、漏查室外空间。外部首轮目视检查也漏掉此角，不能把初核当全通过。

生成端在实际看图时主动发现，通知外部核查者，并另存 v1.1。主要几何修正将 C1 南边界从 y=88 改到 y=94，深度38m变32m，室外面积2736㎡变2304㎡；主建筑块、公众路线与室内面积不变。平面和轴测的浅黄论坛角已回到概念三角边界内。首版原图未覆盖。另将办公进入线 P2 绕开楼梯/电梯预留符号，修正一处剖切字母与尺寸重叠；该细调不改建筑块、公共路线或管理机制。

外部独立脚本 check_geometry.py 在首版复现这一越界，在修正版确认 B1–B4、C1 均在所设边界内，P0未碰封闭地面实体，主备面积加总均为10,080㎡。结果分别见 geometry_check_r00.json 与 geometry_check_v1.1.json。这不是对真实规划边界的验证。

编辑者据此补强 Skill 的完整室外轮廓边界检查。该修补发生在初次生成之后；本报告验证的是本次样例修正和新增条款的存在，**没有宣称重新独立跑过修补后的自然入口全流程**。

## 6. 发布时可说与不可说
可说：“新版本已实际生成一套受控概念样例，并在发现、保留和修正一处室外边界问题后，核查了平面、剖面与体量关系。”
