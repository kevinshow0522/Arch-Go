# 证据如何进入设计

需要引述观点、借用作品机制、使用图示参数或核对覆盖时读取。继承的来源登记是历史记录；本轮维护没有重新浏览外部网页、核读原图或取得书籍正文。

项目来源、可信度、案例深度与本研究的取得/阅读状态按[调用约定](workflow-contract.md)分轴记录。原文观察或历史已读不自动变成项目✔确认，AI不因完成校验自行升级用户确认。

## 分开回答四个问题

| 维度 | 应保存的内容 | 不能推出什么 |
| --- | --- | --- |
| 谁的陈述 | 本人回答、采访者提问、团队项目说明、编者介绍、本研究推论 | 团队作品不自动等于个人独立主创 |
| 取得什么 | 元数据、目录、公开片段、完整文件；文件/URL与取得日期 | 销售页或完整文件不等于已经通读 |
| 实际读到什么 | 定位片段、文本核读、拼板概览、逐图核读；页段及未读部分 | 缩略图可辨体量不等于能辨构造和尺寸 |
| 本次怎样采用 | 原案例事实、条件性机制、本项目假设或决定；依赖条件 | 研究转译不能写成作者原话或通用法则 |

网页用来源ID、URL、标题/小标题和定位段落；网页行号会变，不能单独作稳定定位。书内引用另存版本、文件SHA256、PDF物理页及印刷页码（或EPUB定位）。无法确认的页码留空。图片保留来源图号、像素和阅读方式，区分O观察、T说明、I推论、U未知。

## 什么时候重核原始来源

一般条件讨论可引用已保存的研究卡，同时说明是既有阅读记录。遇到直接引语、精确尺寸、署名争议、互相冲突的描述、现行运营/开放状态，或结论将据此落入正式成果时，回到对应原文/原图；不能访问则保留局部待核，不阻断不依赖它的判断。法规、安全和性能数值依实际项目另核官方现行依据。

J01—J06的理论来源定位在 `index/sources_v06_theory.json`，图像定位在 `index/sources_v06_drawings.json`。这两份为分项记录；`index/sources_v06.json` 是继承的合并快照，维护时须与分项记录逐条一致，不能挑对结论有利的一份。旧S/E编号与V0.5记录保留原适用范围。七大研究主题、季展主题与绿色指引分类不合并成同一公式。

## 迁移一项机制前的最小核对

写清“原案例条件 → 可观察关系 → 可能的作用机制 → 本项目差异 → 修改后的动作 → 验证方式”。机制是研究假说；没有使用评价或性能研究时，不从建成照片证明因果或使用效果。

例如公共路线候选不仅核连通，还核开放时段、受控边界、雨天/冬季使用和后勤交叉。若项目缺乏真实接点或开放条件，就改用旁路或局部共享，而不是继续复制穿行姿态。这个例子是研究者测试方法，不是作者原话。

新阅读记录须绑定具体来源和页段，分开标登记、片段核读、完整核读、待核、跳过及原因。不以卡片数量代替理解，不因脚本通过升级阅读状态。项目实践的复盘也只说明该条件下的结果；升格为通用规则需要新的反例检查与来源依据。
