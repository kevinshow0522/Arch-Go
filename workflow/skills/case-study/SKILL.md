# 案例研究（04 章）v0.6

## 本机接口：KI-design（按需）

借鉴问题需要空间机制分析且入选来源足够时，读取 [KI-design](../ki-design/SKILL.md) 及其 [调用约定](../ki-design/references/workflow-contract.md)，提取原例条件、可观察关系、成立条件、本案差异与失效条件，填回现有案例卡。

04.1的问题按当前主流程引用C02/C03；中途进场可引用已有C/P。资料深度使用甲/乙/丙/原理，与来源等级和阅读状态分开。04.7只汇总已存卡片，不再加载原始研究、不提出或选定方案；证据缺口返回案例工作包。

本 skill 管建筑项目的案例研究：借鉴什么问题、去哪找、资料够不够、怎么写成能给 05 用的结论。流程、交接、事实来源等级 A–E、可信度四档（✔ ● ◐ ○）、编号以主流程 skill 为准。

**先问题，后案例。** 案例数量由借鉴问题决定，不设下限，也没有固定数量。没有合适案例是正常结果，写明原因即可，这一章不算缺项。

各深度做什么（主流程第 2 节）：概念方案（b）04.1、04.7 必做，深拆按需。项目策划（a）的对标案例并在 W2.1 里做，给立项测算当依据，不另开 W4.1；对标问题、对标卡、数字的可信度和对标结论都按 brief-and-metrics 的“策划深度的对标案例”，本 skill 只借给它检索记录表和不凑数的原则。方案设计（c）只为细部问题补查。全部借鉴问题都没有合适参考时，W4.1 照样出 04.7 简版：写明查过哪些渠道、为什么没有、改用什么原理资料。

## 验收清单

（2026-11-26 用户定）结案前逐条答“有 / 没有 / 在哪”，写进结案的检查依据；有“没有”的不结案（主流程第 4 节“把关与对齐”）。都是下文已有的硬规则，不另加要求。

**W4.1**
1. 每个 Q 注明了来自哪条矛盾候选、可能影响 05 的哪个条目、至少需要什么案例等级。
2. 每个参考有可点开的链接或文件位置；规模、面积、年份这些数字来源里有才写，没有凭记忆写的。
3. 每个 Q 有一行检索记录；找不到的写了改用原理资料或“无合适参考”。
4. 每张案例卡对得上至少一个 Q；第 4 栏只写了等级允许的条目；丙级没有单独开卡。
5. 04.7 每条结论追得到案例卡，没有提方案；互相冲突的做法列成了权衡项 T。
6. 没有引用 P，没有自己编 C1–C5；章末摘要已存，标“待确认”。

**W4.2**
1. 写明了深拆是为了回答哪个 Q，这个 Q 要看平面、剖面才能回答。
2. 做平面剖面分析的案例是甲级：有平面和剖面（或总平），加一项可核对的数据。
3. 深拆后的卡仍是 7 栏，第 6 栏写了成立条件与项目差异，第 7 栏写了不能下结论的地方。

## 开工

1. 读设计主线卡（第 2、3 栏的矛盾候选 C02-、C03-，有哪栏读哪栏）、最近交接记录、02.7 任务书；03.8 已经有就一起读，还没出来就先按 C02- 开工。中途进场、已有完整主线卡的项目，可以直接读已有的 C、P；从 05 进入又没有案例的，在 05.1 里写一两条借鉴即可，不回头补 04。
2. 判断建筑类型，读 brief-and-metrics 里对应的类型参考卡。
3. 读本地项目资料或用户资料库前问用户一次：说清本包要读写哪个项目、哪几个区。本包内按这个范围连续做，超出范围再问；段内连续做时由段总控在本段开工时一次问清（主流程第 9 节）。

## 借鉴问题（W4.1 第一步）

- 先从 02.7 的矛盾候选 C02-n 写出 Q（项目策划阶段写过对标问题的，接着它的编号往下编）；03.8 出来后，再按 C03-n 和 03.8 的启示补一两条。合起来一般 3–5 个。每个 Q 是一个设计要解决的问题，例如“消防车库和社会停车共用场地时，出车线怎么不被堵”，不写“找几个好看的停车楼”。
- 每个 Q 注明来自哪条矛盾候选（如 Q2 ← C03-2）、可能影响 05 的哪个条目（如 05.4），以及回答它至少需要什么案例等级：要看平面、剖面、流线就要甲；看立面材料乙就够；问题本身是技术原理的，直接查原理资料。
- 本章不引用 P，也不自己编 C1–C5，这两样在 05.1 才产生。中途进场、已有主线卡的项目可以直接引用已有的 C、P。
- 参考分三类：同类案例（同类型、相近规模）、跨类型类比（类型不同但解决同样的问题）、原理与图集。同类找不到时先找跨类型，再找原理。

## 检索顺序

按顺序查，前一层能回答问题就不往下翻：

1. 用户的资料库（参考优秀文本、过往项目、甲方给的参考）：用户提供或拖进对话。
2. 中文平台：谷德 gooood、ArchDaily 中国、有方、建筑学报等期刊。
3. 外文平台：ArchDaily、Divisare、事务所官网。
4. 规划公示、新闻报道：补规模、投资、建设和运营情况。
5. 规范、图集、设计原理：没有合适案例时的替代来源；条文以用户手里的正式版为准。

规则：
- 每个参考都要留可点开的链接或文件位置。AI 不凭记忆写案例的规模、车位数、面积、年份；来源里找不到就空着。
- 图片只引用链接并注明来源，不存副本；展示要用时再确认版权。
- GPT 和 Claude 都能检索，谁接到 W4.1 谁查，用同一张检索记录表。

## 案例等级

案例等级（甲 / 乙 / 丙 / 原理）说的是这个案例的资料够研究到哪一步，和主流程里单条事实的来源等级 A–E 是两回事：案例卡里的每个数字仍要标来源等级。

这套等级看的是图纸齐不齐，只用于概念方案和方案设计深度的设计借鉴。项目策划深度的对标要的是规模、投资、运营的数字，一份只有文字的立项批复就是最好的来源，所以对标不用甲／乙／丙，也不另设等级，每个数字直接标可信度（brief-and-metrics，2026-11-28 用户定）。策划阶段的对标卡带到概念方案时可以接着用：要回答设计上的借鉴问题，再按下表定案例等级，够等级才补研究条目。

| 等级 | 门槛 | 能写的条目 | 不能做的事 |
| --- | --- | --- | --- |
| 甲 | 至少有平面和剖面（或总平），加 1 项可核对的数据（面积、车位数等） | 04.2–04.6 全部 | — |
| 乙 | 有实景照片，加建筑师、地点、年份 | 04.5 形态材料；04.2、04.6 只写观察到的 | 不做平剖分析，不引用规模数据 |
| 丙 | 只有文字报道或二手转载 | 只进检索记录，作线索 | 不单独开卡，不下结论 |
| 原理 | 规范、图集、教科书 | 写进 04.7 的成立条件 | 不当作案例 |

降级规则：数据在来源里找不到，或只有二手转载，按低一级算。等级后面标可信度（主流程第 5 节）：有可点开的原始来源标 ●，只有二手来源或靠推断的标 ◐；AI 不能标 ✔，用户看过确认后才升 ✔。

## 不凑数：停止规则

1. **入选门槛**：案例要同时满足能回答至少 1 个 Q、案例等级够回答这个 Q。造型好看、名气大都不算理由。
2. **达标即停**：每个 Q 找到 1 个够等级的参考就可以停，最多留 3 个；一个案例可以同时回答几个 Q。
3. **查过留痕**：每个 Q 最多查 3 个渠道，每个 Q 写一行检索记录。
4. **找不到就写不适用**：查完 3 个渠道仍没有够等级的参考，就改用原理资料，或者写“无合适参考”。
5. **展示不设下限**：04.7 按最能说明问题的标准挑展示卡，0 张也可以。
6. **一般 3–6 张案例卡**：W4.1 一个包里通常是这个数量；它是常见范围，不是指标，按上面几条该少就少。

检索记录表（每个 Q 一行）：

| Q | 渠道 | 关键词 | 入选 | 淘汰及原因 | 结果 |
| --- | --- | --- | --- | --- | --- |
| Q1 | | | | | 已找到 / 改用原理 / 无合适参考 |

## 案例卡（W4.1；深拆在 W4.2）

一个案例一张卡，固定 7 栏。04.2–04.6 是第 4 栏里的栏目（场地与总体布局、规模指标与功能、平面剖面与空间、形态与材料、建设与运营），不再各自单做；第 4 栏只写等级允许、借鉴问题用得上的几项，其余写“资料不足，不分析”。某个问题要看平面剖面才能回答时，另开 W4.2 把这张卡的相关栏目拆深。

| 栏 | 内容 | 写法 |
| --- | --- | --- |
| 1 基本信息 | 名称、地点、建筑师、年份、规模 | 规模只写来源里有的，没有就空着 |
| 2 来源与等级 | 链接或文件位置、案例等级（甲 / 乙 / 丙）、可信度（✔ ● ◐） | 至少 1 个可点开的来源 |
| 3 回答哪个问题 | Q 编号，及对应的矛盾候选编号（C02-n、C03-n） | 对不上任何 Q 的案例不开卡 |
| 4 研究条目 | 04.2–04.6 中等级允许的几项 | 每项 2–4 句，配 1 张引用图或自绘简图 |
| 5 可借鉴的做法 | 1–3 条，每条一句话 | 写“做法”，不写“风格” |
| 6 成立条件与项目差异 | 这个做法靠什么条件成立；本项目有没有这个条件 | 给 04.7 直接用 |
| 7 不能下结论的地方 | 资料缺什么、哪些是推断 | 没有就写“无” |

需要分析简图时，画法用 architecture-analysis-diagrams；配色跟本项目统一。

## 04.7 借鉴结论（W4.1 的最后一步）

03.8 出来、C03- 相关的借鉴问题补完之后做。只依据已存案例卡的第 3、5、6 栏写，不回头翻原始资料。

成果：
- **借鉴结论表**：问题 · 可借鉴做法 · 成立条件 · 本项目是否具备 · 来自哪张卡 · 可能影响 05 的哪个条目。
- **权衡项**（编号 T1–Tn）：做法之间互相冲突，或超出经济条件时，单独列出。写清是哪几个方面互相冲突、各自的代价（含造价高低），供建筑师在 05 里取舍。设计常常只能顾及几个方面，不要求面面俱到；04 不替 05 做选择。
- **无合适参考的问题**：列出 Q 编号、查过的渠道和改用的原理资料。
- **展示选择**：需要展示时选哪几张卡，说明理由。

规则：
- 每条结论都能追到案例卡；追不到的不写。
- 04.7 不提方案，只写做法、条件和差异。
- 04.7 做完按主流程第 4 节结案，由段总控交回主总控，和 03.8 在“场地与案例”段末一起确认；用户在主总控确认后，结论和权衡项写进设计主线卡第 4 栏，供 05.1 引用。

## 结束

成果存入项目服务，注明引用的主线卡版本；写一条交接记录（做了哪些条目、Q 编号与检索结果、案例卡编号、待核对项、下一包），包就默认结案（主流程第 4 节）；W4.1 做完就是本章章末，交给段总控。
