# KI 工作流中的建模交接

仅在本次任务属于 KI建筑设计工作流时使用。本 Skill 也可独立建模；独立任务不自动建业务项目、补八章或要求安装其他 Skill。

## 职责与调用位置

主流程 [ki-archmain](../../ki-archmain/SKILL.md) 管项目、工作包、执行者、版本和确认；章节方法决定本轮成果；[KI-design](../../ki-design/references/workflow-contract.md) 提供空间判断。建模 Skill 接受当前任务，把已讨论的空间动作转成可编辑几何并检验，不自行另定方向或更改分工。当前任务的明确用户授权持续有效，不重复索要相同授权。

| 位置 | 建模参与范围 |
| --- | --- |
| 03 场地研究 | 按需验证地形、周边及场地空间关系；来源不明的高程、红线与建筑高度保留未知或显式假设 |
| 05 W5.2 | 接收步骤卡和建模任务单，按方向制作总平/体量、必要剖切及同机位导出；主要建模入口 |
| 05 W5.3/W5.4 | 在同方向模型中按需验证功能、流线、立面及重点空间，不自动重做全案 |
| 06 方案深化、06.6 图模协同 | 承接已选方向及具体平剖立面修改，核关联几何，返回图模差异与专业接口 |
| 07 展示 | 从同版模型导出和核对图件；需要改变设计几何时返回对应05/06任务 |
| 08 交付 | 检查实际文件、版本、资源、可编辑范围和归档清单 |

调用本 Skill 不自动新建聊天或转派任务；分工和工作包停点沿主工作流。一个工具阶段结束不代表一个设计工作包结束。

## 接收现有任务单

从当前上下文、项目服务和已存文件中提取；缺什么只补依赖它的部分，不让用户重填表。内容直接补入现有建模任务单或交接记录，不维护第二张主线卡。

- 本次用途、章节/工作包、方向与步骤号、需要交回的模型和图件。
- 主线、指标和底稿模型的版本；相应 C/P 编号（仅引用已经存在的编号，03不新造05的策略）。
- 各来源的角色：哪份图纸或模型控制几何，哪张图片只供材料/氛围参考，哪项尺寸有可靠出处。冲突按指定控制依据核查，不能让效果图覆盖已确认几何。
- 有效尺寸、单位、项目原点、北向、标高基准和必要坐标变换。未知值沿用工作流的来源等级与可信度；假设不升级为规划硬限制或指标目标。
- 本轮可变对象、必须保留对象、共享组件影响范围；源文件与输出目录的现有授权。
- 检查重点及结束条件，例如院落连通、体量高度、某跨开口、同机位比选；不按工具阶段数添加设计目标。

不把 `kg_` 项目/任务 ID 当作 `sketchup_project_*` 的 `project_id`。在原工作包中关联两套 ID、模型路径与工具工作单元；不为每个构件或工具阶段另建业务项目。

## 设计步骤与建模步骤

按 [concept-scheme](../../concept-scheme/SKILL.md) 的现行步骤卡执行：C/P → 空间动作 → 几何变化 → 检查及代价。一个设计动作可能需要多笔工具操作；主形、样板、复制属于制作顺序，不另编成设计理由。

每个需要展示的设计步骤，保留对应的可恢复几何状态或实际独立副本，再关联场景和导出。场景命名沿用步骤号，如 A-03-退；不能让所有步骤实际指向最后一个形体。按任务需要选择快照或隔离的步骤容器，不复制无关全模型。

同方向与方向间比较沿用统一单位、有效条件、指标口径、机位和输出尺寸。一般采用任务单约定的顶视和分析机位；必要剖切补充空间证据。面积/容量读取须说明净毛、地上地下、范围及版本；包围盒不代替建筑面积或停车容量核算。

原模型与导入底稿保留可恢复版本，正式修改放在已授权工作副本。局部更新先核目标、祖先容器和共享定义；修改后同时读回目标与受保护对象。不通过新建重叠副本冒充修复原对象。

## 单位与坐标只在接口边界转换

工作流任务单可按米表达；typed operations 和 `context['geometry']` 的长度输入按毫米组织，例如 `6 m → 6000 mm`。不要将已换算值再乘1000，也不要先调用 `.mm` 再传给毫米 helper。原生 Ruby API 的单位处理沿[受管 Ruby API](managed-ruby-api.md)，不要混用裸数值。

地理/CAD基准转换到模型局部坐标时保留实际平移、旋转、比例及标高关系；已有底稿已完成转换就直接沿用。缺少控制点或基准时不伪造“已配准”。用真实读回检查一个已知跨度、关键标高和相关定位关系，而非只检查脚本输入。

可靠且口径匹配的尺寸可绑定 `task_profile.dimension_targets`，见[尺寸检查](source-dimensions.md)。对象局部跨度不等于绝对标高或面积；推断值不冒充已确认目标。已有绑定目标变更须核对工具允许的迁移方式，不手改受管签名、强填新哈希或另起任务绕过已知失败。

## 检查、设计确认与交付

1. **几何与文件检查**：实际尺寸、关系、目标/保留对象、真实图像和输出文件各取相称证据。未检查项明确写未验证，截图已生成不等于已看过。
2. **设计确认**：用户是否采纳当前空间和取舍单独记录。AI技术检查通过不写成用户确认；方向或关键条件需要改变时返回设计讨论。已授权范围内的常规纠错可连续处理。
3. **交付状态**：核实际保存、必要重开或独立读回、资源与可编辑范围；模型完成、工作包完成、章节确认分别记录。做完当前包后按原工作流交接，不自行跨包。

有项目服务时先读该项目实际 storage，按当前授权使用 `working_directory`、`materials_directory` 和 `output_directory`；无服务的既有文件项目沿用原工作流目录。不在 C盘另建平行业务库。

脚本、过程模型、回执和工具签名留在工作目录；交付副本和实际导出图核对后进入成果目录。不能搬动或手改工具状态来完成归档；复制交付文件后核文件与哈希。导出图如仅为检验截图，明确用途，不冒充满足正式图件规格。

原工作包的交接至少关联：主线/指标/模型版本、方向与步骤、工具项目与工作单元、实际SKP及图件路径、已执行检查、推断/未决事项、用户确认状态和下一动作。使用既有服务保存成果、记录及任务状态；写入失败与文件未落盘分别说明。

修改设计几何后检查受影响的步骤、平剖立面、指标、专业接口及07引用；关联成果先标待复核，核对或重导后再更新引用。纯机位/显示修改按影响范围核查。自动发现跨工具依赖和自动同步只有实际验证后才能声称存在。

通用对象保护、恢复及保存依据沿用[已有建模核验](../../ki-archmain/legacy/references/modeling-verification.md)；本页是当前 Skill 的调用接口，不替换章节正本。
