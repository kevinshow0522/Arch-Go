本 skill 管 05 章怎么想、怎么推、怎么比：从上游章末结论提炼关键矛盾，提出多个方向，按步骤推体量，最后比选定向。图怎么画不在这里：B1 体量生成、B2 功能、B9 流线用 architecture-analysis-diagrams；效果图由 Claude 写提示词、GPT 生图。流程、交接、来源等级与可信度、编号、主线卡栏目、分工以主流程 skill（ki-archmain）为准。

**分工**：Claude 做推演思路、步骤卡、CAD 草图（总平、剖面示意）和分析图，写给 GPT 的建模任务单和效果图提示词；GPT 建模（SU / Rhino）、出场景和导出图、生成效果图；用户讨论、核对、拍板。

**核心是一条可追溯的链**：设计思路 → 关键矛盾 C → 理念 → 策略 P → 每一步体量动作 → 比选。每个下游成果（图、文字、模型场景）都要能指回某条 P 和某条 C；指不回去的就是孤立内容，要么补上来源，要么删掉。

## W5.1 设计主线与方向粗选

### 两种入口

- **正向推演**：上游四个章末结论已有，先谈定设计思路，再按步骤 1–6 做。
- **中途进场**：不做逆向补卡（2026-11-28 用户定），不从已有方案反推矛盾和策略，从进入的那一章起照方法定的章节和条目接着做。从 05.1 进的照样先谈设计思路；从 05.2 以后进或只出图的，写进场卡就开工，成果对上进场卡的锁定项和本次目标（主流程第 2 节）。

### 先谈定设计思路

（2026-11-28 用户定）设计思路从前四章的分析和总结里得出，谈定了再提方向。

**讨论底稿**：只读已确认的 01.5、02.7、03.8、04.7 和主线卡第 1–4 栏，写一页；不提方向，不做草模。

1. 前四章各给了设计什么，每章一两句带编号：定位和服务范围；约束和 C02-；“05 必须 / 可以 / 不要”和 C03-；可借鉴做法和权衡项 T。
2. 设计思路草稿：三到五句，说清打算怎么做、为什么；每句追得到上面的编号。
3. 要用户定的：关键矛盾怎么排、权衡项各偏哪边、不做什么。

**讨论和确认**：用户已有的想法和想试的方向记下来，必须列为方向之一。谈定后存确认记录“设计思路”，写成 05.1 成果的第一部分。不派复核；没谈定不往下做。

### 步骤

设计思路谈定后做。

1. **关键矛盾 C1–C5**：只从上游章末结论里取，每条写来源候选（02.7 的 C02-n、03.8 的 C03-n，如 C1 = C03-2 + C02-1）；最多 5 条，按确认过的设计思路排序。没有来源的“矛盾”不收。
2. **方向**：针对排前两位的矛盾，提出 3 个以上有实质差异的空间主张。差异必须在布局、体量或剖面上；只换立面、只换材料不算一个方向。用户在讨论设计思路时提的方向必须在内。
3. **一句话理念**：每个方向各一句，说清楚“用什么空间做法回应哪条矛盾”，不写形容词口号。比选前各方向理念并存，比选后锁定一个。
4. **策略 P1–P5**：每条写成“动词＋对象＋结果”，例如“消防车库独立设置，直出南侧道路”。每条注明回应哪个 C、管哪些下游条目。下游成果只引用这些编号，不另换说法。
5. **不做什么、缺口与待定项**：照主线卡格式写。
6. **草模与粗选**：每个方向做一个大关系体量草模，只表达布局、体量或剖面上的主要差异，不做细部。Claude 按方向写草模任务单（方向名、体块关系、关键尺寸、两个机位），GPT 建模并导出同机位图。用户看过矛盾、方向和草模后确认 05.1，挑 1–2 个方向往下做；落选方向的草模和说明存档，各写一句落选理由，不删。

   没有 GPT 端可用时（2026-11-26，测试项目跑完后补）：由 Claude 用脚本出各方向的体量简图代替草模，图上标“简图，不是模型”，照样只表达布局、体量或剖面上的主要差异。挑中方向后的正式模型仍交 GPT 建；还没建的，在交接里写明“建模任务单已写、未执行”，不把简图当模型用。

从 05 中途进入、没有案例研究的，在 05.1 里写一两条借鉴即可（主流程第 2 节“中途进场”）。

## W5.2 体量推演

只做 W5.1 里用户挑中的 1–2 个方向。项目策划深度的强排示意也挂在这里：只做第 0–2 步（容量试算、可建范围、容量体），一个方向，结论是规模放得下还是放不下、差多少，不往下做策略动作。

### 步骤

| 步 | 做什么 | 谁做 | 出什么 |
| --- | --- | --- | --- |
| 0 容量试算 | 把任务书指标换成面积、层数、跨数。例：停车楼 车位数 ÷ 每层车位 → 层数，再定坡道形式（直坡道、螺旋、错层） | AI | 试算表 |
| 1 可建范围 | 红线、退线、限高拉出“能建的盒子” | Claude 写任务单，GPT 建模 | 场景 01 |
| 2 容量体 | 按试算放入初始体块 | Claude 写任务单，GPT 建模 | 场景 02 |
| 3–5 策略动作 | 每步一个动作：切、退、抬、架、分、连、错层等 | Claude 写步骤卡，GPT 建模，用户讨论调整 | 场景 03–05 |
| 6 剖面检查 | 层高、坡道、屋面和场地高差是否成立 | Claude（CAD 剖面示意）＋用户 | 1–2 个剖切示意 |
| 7 总平落位 | 体量回到总平，出入口和室外空间成形 | Claude（CAD 总平草图）＋用户 | 总平草图 |

规则：

- **一步一个动作。** 每一步只做一个形体动作，写一句“因为 C#，所以做什么（P#），得到什么”。一个方向 4–6 步；超过 6 步说明动作太碎，合并。
- **步骤卡是文字正本。** SU/Rhino 场景和 B1 图都按步骤卡编号，三者一一对应。B1 是推演的副产品，不事后另编故事。
- **每一步都存成场景**，用同样两个机位导出：顶视（平行投影正上方）、分析（平行投影等轴）。图片尺寸固定。

**SU 还是 Rhino**：方正体块和常规推演用 SU；曲面形体、参数化立面、要一次比较很多变体时用 Rhino＋Grasshopper。同一个方向只用一个软件的模型作正本，另一个只做辅助，避免两套模型对不上。两个软件的机位名称、视角和导出尺寸保持一致。

建模要求（写进给 GPT 的任务单）：单位米；原点用项目原点（与项目记录里的项目原点一致）；脚本开头写明对应方向和步骤；每次改尺寸改脚本参数区，不在脚本中间散改；脚本和模型存“工作文件/05/模型”。

## W5.3 功能与流线

- 功能按楼层落位，面积回到 02.7 指标表核对。
- 出入口位置以 03 的四边界面表为依据，写明用的是哪条边、哪条依据。
- 流线分类别画（如车行、人行、消防、后勤），所有图同色同义；关键交叉点单独说明怎么避开。

## W5.4 立面、环境与重点空间

- 立面写“表情”而不是样式：朝哪个对象、要藏什么、要显什么，对应哪条 P。
- 05.6 只做建筑层面的被动策略（朝向、采光、遮阳、自然通风），不补结构、机电等其他专业内容。
- 效果图由 Claude 写提示词，另建任务交给 GPT 生图，不在本对话里等待。提示词按下面的任务单写。

### 效果图提示词任务单

Claude 写，用户看过同意后交 GPT 生图。全流程和中途进场的直出共用这一张：

| 项 | 写什么 |
| --- | --- |
| 1 底图或参考图 | 模型同机位导出图的文件名；或文档名加页码；没有就写“无” |
| 2 锁定项 | 不许改的：体量、层数、立面分格、开洞、出入口等。没有底图时写“无，纯意向” |
| 3 场景 | 视角与机位、时间与天气、季节、人的活动、前景与配景 |
| 4 材料与色彩 | 主要材料、质感、色彩倾向，与主线卡表达基准一致 |
| 5 对应 | 全流程写方向和策略 P 编号；直出写进场卡里的本次目标 |

## W5.5 比选与定向（章末）

**先做指标与估算速核**（原 W5.5a，2026-11-25 并入本包；做法见主流程第 10 节）：留下的每个方向一行，面积、容量、效率指标对照指标表目标行，再按单方造价经验值给估算区间，标 ◐。结果用在下面第 4、6 两个维度。

**只留下一个方向时**，不硬凑比选表：05.9 写明它和落选方向相比的理由（引用 W5.1 的落选理由和草模），过了第一关门槛就定向。挑中两个方向时，照下面两关比。

**第一关，门槛（不过就出局）**：指标达不到任务书；消防或规范有硬伤；违反规划条件（限高、退线、出入口）；主线卡第 3 栏的“05 必须”有哪条没满足，按编号（必1、必2……）一条条对。指标表目标行缺容量或效率指标的，速核只能对量级，在比选表里写明。门槛用到的硬限制或甲方目标，如果记着“待取得正式文件”或“待甲方书面确认”（主流程第 5 节），在比选表的门槛行注明是哪一条；靠这一条过关或出局的，05.9 的结论写成“以取得该文件或书面确认为条件”，拿到后复核。

**第二关，6 个维度定性比较**，每格用文字写 好 / 一般 / 弱，加一句理由，不算总分（✔ ● ◐ ○ 只表示可信度，这里不用）：

| 维度 | 看什么 |
| --- | --- |
| 1 回应关键矛盾 | 逐条看 C1–C5，权重最高 |
| 2 场地关系 | 是否用好了 03.8 的“可利用、要保留” |
| 3 使用与流线 | 好不好用，流线是否清楚 |
| 4 指标与效率 | 容量、面积效率（如停车楼看单车位面积） |
| 5 形象与城市界面 | 对街、对周边敏感对象、对景观面的表情 |
| 6 投入与实施 | 造价高低、施工难度、能否分期 |

## 收尾

1. 成果存入项目服务，注明引用了主线卡哪一版、05.1 的哪条策略（例如“主线卡 v0.2 · 05.1 的 P1”）。
2. 写一条交接记录：本包做了什么、用了哪些场景和导出图、留下的待定项。
3. 用户的确认写成记录，不靠对话记忆。
4. 包做完默认结案，交接给本段下一个包或 W5.5；下一个包没有方向抉择就由段总控接着开，要用户选方向、定方向的地方照旧停下来和用户讨论（主流程第 3、4 节）。方向和草模出来后，W5.1 的对话先派只读的复核子代理（派不了的请段总控派），再把 05.1、草模和复核意见一起摆给用户；用户在这个对话里直接确认 05.1 并挑方向。确认后写确认记录，05.1 的章末摘要改成“已确认”，主线卡先不写，然后交接给段总控。W5.5 做完按主流程第 4 节结案，由段总控交回主总控；用户在主总控拍板后，矛盾、方向、策略和已定方向（第 5–8 栏）一起写进设计主线卡，卡升 v1。05.1 和 05.9 做完都要按 ki-archmain 同步工作台。

## 不做什么

- 不为凑数加方向：方向之间没有实质差异就合并。
- 不在效果图上画分析，不拿效果图当几何依据。
- 不补结构体系等其他专业内容（框架范围只到建筑概念设计）。
- 不跳过门槛直接比好看。

## 出 07 展示前的统一性校核

1. 每张图、每段文字都能对上至少一条策略（P1–P5），没有孤立内容。
2. 没有和已确认结论冲突的说法；有冲突先走变更流程。
3. 功能色、流线色、术语和主线卡完全一致。
4. 数字（面积、容量）全部来自同一张指标表。
5. 推断内容都已标注，或已按总平面图核对过。
